# Slice 2.6 — Reconciliation

*Merged 2026-11-11 · [PR #19](https://github.com/AdamDiouri/idem/pull/19) · [plan](../superpowers/plans/2026-11-11-slice-2.6-reconciliation.md)*

The last slice of milestone 2. idem's ledger and the provider are two separate records of the same money; `idem reconcile` audits one against the other through the provider's own report, records every difference, and changes nothing (D15). Every chaos campaign now ends with it.

## What shipped

- **The provider's report.** The fake provider serves a production-style, paginated balance-transactions report: one signed row per money movement, with workflow metadata (a payout appears only once paid). idem's provider client reads every page and fails the whole read on a bad page: it never reconciles half a report.
- **`idem reconcile`.** Per movement: each provider movement created in the window must have its posting (matched through the step's provider reference; a posting's `provider_receivable` entry is signed exactly like the provider's amount, and the currency must match too), and each posting created in the window its movement, looked for up to 24 hours before the window. At most one discrepancy per workflow and type: `duplicate_effect`, `amount_mismatch`, `status_mismatch`, `missing_in_ledger`, `missing_at_provider`. Steps still in flight are skipped; parked workflows are reported and flagged. Exit codes `0` clean, `3` drift, `1` failed.
- **Open until fixed.** A discrepancy stays open (the gauge, the alert, `idem admin recon list`) until a later run whose window contains it no longer finds it.
- **Operators:** `idem admin recon list`; a parked workflow's differences shown next to it in `idem admin list`; gauges from the sweeper; alerts `IdemReconciliationDrift` (page) and `IdemReconciliationStale`; runbook sections per kind; a compose service reconciling every 10 minutes.
- **Invariant RECON in chaos:** the closing reconciliation, through the production path, must report nothing outside parked workflows, and exactly the real differences for parked ones.

## What broke or surprised us

- **Time is the hard part, and my first design got it wrong.** The plan let the window select workflows and then compared each on everything known about it, with the report read an hour beyond both edges. The final review (C1) showed that an honest payout settling more than an hour after its charge then reads as `missing_at_provider` for the charge's hour, and that in production that is the common case. The redesign judges each movement and each posting in its own window, so history outside the window is never judged. `TestRun_SettlementLongerThanTheMargin` pins it.
- **The report and the database are read at different moments.** The review (I3) also caught a race: a movement made while the report was being read could be judged against a ledger read later. idem's state is now read first, in one read-only repeatable-read snapshot held while the report is fetched, so a later movement belongs to a step the snapshot shows in flight. `TestRun_SnapshotBeforeReport` failed before the change.
- **"Latest run" was the wrong gauge (I2).** An hourly run over a quiet hour would clear the alert for a difference found an hour before. Discrepancies now stay open until a covering run no longer finds them (a view, `recon_open_discrepancies`).
- **Trusting the report's shape (I1).** The client now rejects a page with no `data`, rows without an id, type or time, and a cursor that does not advance (the test hung before the fix).
- **"Clean" counts surprised me once.** A declined workflow moved nothing on either side, so nothing anchors it to a window: the first test expected three workflows compared and got two, which is right.
- **My own slips:** a commit went in with a failing test because a pipe hid the exit code (amended, and later commands gate on the code); one test called `testutil.NewPool` twice and so truncated its own data; one parked-workflow test drained the payout before lowering its attempt limit.
- **What chaos does not exercise:** the campaigns park workflows only by the pivot rule, where the charge moved and is posted and the payout never moved, so the ledger matches and RECON correctly expects nothing. A parked workflow whose ledger truly differs is proven by tests (`TestRun_ParkedWorkflowIsReportedAndFlagged`, `TestRECON_ParkedMustBeReportedExactly`), not by a campaign.

## Evidence

- Chaos campaigns, seeds 1, 2 and 3 (90s): PASSED, 0 violations; after the review's fix pass the closing reconciliation compared 841, 827 and 841 workflows with 0 discrepancies.
- Tests: classification for every kind and precedence; real workflows of every outcome reconciling to nothing; F34 both ways (a charge made outside idem; a posting with no movement); a stray charge on a declined workflow (`status_mismatch`); in-flight skipped; a provider outage failing the run with nothing reported; and a byte-for-byte check that a run changes no workflow, step, ledger or outbox row.
- Compose smoke: a clean run (exit 0), then a stray charge at the provider reported as `duplicate_effect` (exit 3), visible in `idem admin recon list` and in the sweeper's gauge.
- `make test`, `make lint`, `make vuln`, `make build-release`, 18 alert rules.
