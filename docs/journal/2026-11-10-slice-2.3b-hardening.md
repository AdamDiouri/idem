# Slice 2.3b — Hardening

*Merged 2026-11-10 · [PR #11](https://github.com/AdamDiouri/idem/pull/11) · [plan](../superpowers/plans/2026-11-10-slice-2.3b-hardening.md) · written retrospectively on 2026-11-10 from the PR and commit record*

A slice inserted between 2.3 and 2.4. An external review of milestones 1 to 2.3 found gaps, and we closed them before moving on. The main one: chaos could pass while the webhook path was broken, because polling completes every payout anyway.

Around this slice: [PR #12](https://github.com/AdamDiouri/idem/pull/12) followed with GitHub Actions CI and a move to Go 1.27.4, after govulncheck found 28 reachable standard-library vulnerabilities under Go 1.25.6.

## What shipped

- **The webhook verdict checks what the inbox did.** Chaos waits for the provider's webhook queue to drain before judging. A new invariant, I11, and a stricter I10 check the inbox event by event against the provider's delivery log: every acknowledged event is stored, none was accepted on a forged signature, none was stored that the provider never sent, and an "applied" event left a webhook attempt on its step.
- **Non-vacuity for webhooks.** Webhooks must actually complete payouts, counted from the steps' attempts. In longer runs, a reordered event must have been recognised as stale.
- **Tighter invariants.** I6 holds in both directions, backed by a UNIQUE constraint. I3 skips only parked workflows whose outcome is unknown. I7 requires a refund to equal its charge.
- **A hook that keeps failing parks its step** (`hook_failed`) after `IDEM_HOOK_MAX_FAILURES`. Before this, a poll whose success hook always failed looped forever; we reproduced it first (7 failures in 8 rounds, never parked).
- **The ledger is append-only by privilege.** The API, workers and sweepers log in as a member of `idem_app`, which cannot UPDATE, DELETE or TRUNCATE ledger rows or the audit trail. The whole test suite and every chaos process run as that restricted role.
- **F24 and F26 actually tested.** F24 (clock skew): a static test checks that no lease or schedule query takes a time from Go. F26 (rolling deploy): a `restart_all` chaos event restarts every process at once during traffic.

## What broke or surprised us

- **A refused send whose failure hook kept failing looked like doubt.** It was parked with an attempt recorded `DEAD`, which counts as send-doubt, so an operator's later `retry-step` would have been parked again by the pivot rule instead of compensating. It now ends `hook_failed_no_effect`, with no false "money may have moved" page.
- **`EnsureAppUser` could take over any existing role,** including the owner or a superuser, silently voiding the privilege guarantee. We first added a guard, then removed the function: creating logins belongs to infrastructure, and `idem migrate` no longer needs the right to create roles.
- **Our new I10 rule was wrong.** The first campaigns (seeds 1, 3, 1202) failed on it. It required every stale event to be ignored, but a stale event that reaches a payout still waiting is applied by design, with the re-checked state. I3 and I7 were clean in every run. We corrected the rule, test first.
- **The first "webhooks completed payouts" check trusted the inbox's own label.** An inbox that labelled events applied without applying them would have passed. Found while preparing the mutation checks, and fixed before running them.
- **Ten review minors fixed,** each with a test that failed first. Among them: deadlocks and lock timeouts inside a hook no longer count as hook failures; a `hook_failed` step keeps the provider's reference for `confirm-step`; every oracle read has a timeout; migration 00013 rolls back with plain REVOKEs that a managed-Postgres owner can run.

## Evidence

- Campaigns on the final build: seeds 1, 2, 3 (90s) and 1202 (60s) passed with 0 violations, 0 webhooks in flight at the verdict, 526 to 624 payouts completed by webhook, 17 to 19 stale events ignored, and `restart_all` effective 1 to 3 times per run.
- Mutation checks (seed 1, 60s), each a deliberately broken binary that chaos had to fail: an API that accepts any signature (40 I11 violations); an inbox that labels without applying (I11 on every event, and "no webhook completed a payout"); stale detection removed (I10 conflicts, and no reordered event recognised).
- `make test` (15 packages, as the restricted role), `make lint` 0 issues, chaos-tagged tests 3 times in a row, `promtool check rules` (14 rules).
- Compose: on a fresh volume the init script created the login and a payout succeeded; `DELETE FROM ledger_entries` as the app user was refused.
