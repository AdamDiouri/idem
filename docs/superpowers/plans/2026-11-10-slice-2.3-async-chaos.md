# Slice 2.3: Async Chaos — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chaos campaigns break the asynchronous paths on purpose and still find zero violations. Concretely:
- every webhook fault is injected
- the two new failpoints are armed
- the API runs as **two replicas**, with clients and webhooks spread across both
- the verdict refuses to pass unless each of those actually happened

Database connection-pool metrics make "is the pool a bottleneck?" measurable.

**Architecture:**
- **Pool metrics:** a Prometheus collector reads pgx's own pool statistics on each scrape.
- **Failpoint names:** a failpoint that exits now writes its name to stderr first, so the harness can tell which one fired.
- **The fake provider** rotates webhook deliveries across several URLs. A retry goes to the next replica, so deduplication is proven across replicas.
- **The chaos plan** adds the webhook faults to its random fault sets and guarantees each one appears in runs of a minute or more. API restarts target one replica at a time.

**Tech Stack:** Go 1.25, pgx/v5 v5.12.0 (`pgxpool.Stat`), client_golang v1.24.0, the existing chaos harness.

**Spec:** `docs/superpowers/specs/2026-11-10-milestone-2-design.md`:
- §10, the slice 2.3 row, including the owner's two-replica decision
- §8: F15–F17, F19, F28–F30 at process level
- §9: I4, I6, I10

Also `docs/design.md` §14.3 (the chaos verdict).

## Global Constraints

- Go 1.25 with `GOTOOLCHAIN=local`; no new dependencies.
- **The chaos verdict stays strict and never vacuous.** Anything armed must be shown to have fired. Any parking other than `permanent_after_in_doubt` fails the run. Any `CONFLICT` row fails it too (I10: the fake provider never truly contradicts itself).
- **The fake provider stays the oracle:** it is never restarted.
- **Metric labels never carry IDs.** Pool metrics carry no labels, because each process has one pool.
- Commits never carry a `Co-Authored-By` line. `make test`, `make lint` and `make build-release` pass at the end of every task. Chaos-tagged tests pass from Task 4 on.

## Review Focus

1. **A webhook stored by one replica, which then crashes before answering, and retried to the other replica,** must be a duplicate there: one inbox row, applied once. Test: Task 3 `TestWebhooks_CrossReplicaRetryIsDuplicate`.
2. **The same `Idempotency-Key` sent at the same moment to both replicas** must create one workflow, and both callers get the same body (I6). Test: Task 4 `TestE2E_SameKeyOnTwoReplicasIsOneWorkflow`.
3. **While one replica restarts,** clients rotating across replicas must still get every workflow accepted through the other: no client request is lost. Test: Task 4 `TestClients_SurviveOneReplicaDown`.
4. **Metrics turned off** (`IDEM_METRICS_ADDR=off`, so nil metrics) must not panic when the pool is watched. Test: Task 1 `TestWatchPool_NilMetricsIsNoop`.
5. **A run where a webhook fault was armed but no payout settled while it was active** must be judged vacuous for that mode, not passed. Test: Task 3 `TestReport_WebhookFaultArmedButNeverFiredIsVacuous`.

### Task 3: Webhook faults in campaigns, delivered across replicas

**Files:**
- Modify:
  - fake provider: `internal/fakeprovider/provider.go`, `internal/fakeprovider/webhooks.go`, `cmd/fakeprovider/main.go`
  - chaos: `internal/chaos/plan.go`, `internal/chaos/report.go`

  - chaos: `internal/chaos/plan_test.go`, `internal/chaos/report_test.go`
  - API: `internal/api/webhooks_test.go`

**Interfaces:**
- Produces:
  - **`fakeprovider.Options.WebhookURLs []string`,** replacing `WebhookURL`. Attempt *n* of a delivery goes to `WebhookURLs[(index + n) % len]`, where `index` is the delivery's position in the queue, so a retry lands on the next URL. `FAKEPROVIDER_WEBHOOK_URL` accepts a comma-separated list.
  - **`WebhookDelivery.Targets []string`:** the URL of each attempt, for the oracle and tests.
  - **The plan:**
    - `endpointModes["webhooks"]` = the six webhook modes, and `"webhooks"` is added to `endpoints`
    - for runs of a minute or more, `NewPlan` makes sure **each webhook mode** appears in at least one `SetProviderFaults` event, appending one event per missing mode at a random time in the window, as it already does for kinds
    - webhook rules use probability 0.2–0.5, so they meet payouts
  - **The report:**
    - `FaultHits` already counts `webhooks/<mode>`
    - **Verdict:** for every webhook mode that appears in an *effective* `SetProviderFaults` event, `FaultHits["webhooks/<mode>"]` must be ≥ 1; otherwise `vacuous: webhook fault <mode> was armed but never fired`
    - I10 (no `CONFLICT`) is already enforced by `invariants.Check`; the report lists `conflicts: 0`

### Task 4: Two API replicas in chaos, with API failpoints

**Files:**
- Modify: `internal/chaos/run.go`, `internal/chaos/plan.go`, `internal/chaos/clients.go`, `internal/chaos/report.go`, `cmd/chaos/main.go`
- Test: `internal/chaos/clients_test.go`, `internal/chaos/plan_test.go`, `internal/chaos/report_test.go`, `internal/api/e2e_test.go`

**Interfaces:**
- Produces:
  - **Config:**
    - `Config.APIs int`, default `2` (flag `--apis`)
    - `Config.APIFailpoints` (from Task 2) defaults to `"webhook_after_insert=exit@0.02"` and is passed to each replica
    - workers' default `Failpoints` gains `inbox_before_commit=exit@0.02`
  - **The plan:** `PlanConfig.APIs int`; a `RestartAPI` event gets `Target = rng.IntN(APIs)`, and `apply` restarts only `apis[Target]`.
  - **Clients:**
    - `ClientConfig.BaseURLs []string`, replacing `BaseURL`. Every request, including retries and double-clicks, takes the next URL from an atomic round-robin counter, so a retry usually lands on the other replica.
    - `ClientResult.PerReplica map[string]int` counts the requests each URL *answered* (any HTTP status).
  - **Run:**
    - starts `APIs` processes named `api-0`, `api-1`, each with its own port and `IDEM_FAILPOINTS=<APIFailpoints>`
    - the provider's webhook URLs are every replica's
    - settling restarts each API without failpoints, as for workers
    - `Report.WebhooksStored map[string]int` per replica (log lines `provider webhook stored` in `api-<i>.log`)
  - **Verdict,** when `APIs > 1`: every replica answered at least one client request and stored at least one webhook. Otherwise `vacuous: API replica <name> served no …`.
  - **Report text:** `api replicas: 2 (requests api-0=…, api-1=…; webhooks stored api-0=…, api-1=…)`.
