# Slice 2.4: Workflow Status and Outbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shop can read a workflow's true status (`GET /workflows/{id}`), and every terminal transition writes exactly one outbox event in the same transaction (D13), proven by invariant I8.

**Architecture:** The shop's view of a workflow is defined once, as the SQL function `workflow_view(uuid)` (like `step_send_doubt` in 2.3b). `transitionWorkflow` inserts an outbox row with that view as its frozen payload whenever it moves a workflow to a terminal state; `GET` returns the same function's live output, so the two cannot drift. The provider's refusal code is kept in a new `steps.failure_code` column so a failure has a reason the shop can use. Nothing delivers the outbox yet (the relay is slice 2.5): rows stay `PENDING`, which is F33.

**Tech Stack:** Go 1.27.4 (pinned in `go.mod`), Postgres 18, sqlc on pgx/v5, goose, net/http, client_golang.

**Spec:** [M2 design](../specs/2026-11-10-milestone-2-design.md) §5.1, §5.2, §7, §9 (I8), §10 (slice 2.4), §12; [design](../../design.md) §9.1, §11.3; [D13](../../adr/0013-outbox-written-in-transition.md).

## Global Constraints

- Postgres is the only state store (D1). Hand-written SQL through sqlc (D8); run `make generate` after query changes; CI fails on drift.
- Lease and schedule times come from the database's `now()` (D3); the F24 clock guard test must keep passing.
- Every integration test runs as the restricted login (`testutil.NewPool`); schema and corruption tests use `testutil.NewOwnerPool`.
- Terminal workflow statuses: `SUCCEEDED`, `FAILED`, `COMPENSATED`. Event types: `workflow.succeeded`, `workflow.failed`, `workflow.compensated`.
- The outbox row is written inside `transitionWorkflow` and nowhere else. `UNIQUE (workflow_id, type)`; a second event is an error that rolls the transition back, never `ON CONFLICT DO NOTHING`.
- The shop sees no step, ledger, provider or parking internals, and no IDs other than the workflow's (spec §5.1).
- Commits never carry a `Co-Authored-By` line. `make test`, `make lint`, `make vuln`, `make build-release` and the chaos smoke pass; CI is green.

## Decision for the owner to confirm: the public status vocabulary

The spec (§5.1) returns `status` plus, for terminal states, a string `outcome` such as `failed: card_declined`. This plan uses two machine-readable fields instead:

```json
{"workflow_id":"0193…","status":"failed","reason":"card_declined","amount_cents":10000,"fee_cents":175,"currency":"EUR","created_at":"2026-11-10T09:00:00.123456Z","updated_at":"2026-11-10T09:00:01.654321Z"}
```

- `status` is one of `processing`, `succeeded`, `failed`, `compensated`. `PENDING`, `RUNNING`, `COMPENSATING` and `NEEDS_ATTENTION` are all `processing`: none is an outcome yet, and parking is internal (spec §5.1).
- `reason` is present only for `failed` and `compensated`: for `failed`, the charge's provider refusal code if it is a plain token (`^[a-z][a-z0-9_]{0,63}$`), else `charge_failed`; for `compensated`, always `payout_failed`.
- Why: a shop branches on `status` and shows `reason`; parsing `"failed: card_declined"` invites bugs. The spec's information is unchanged. Task 6 updates spec §5.1 to match.

## Review Focus

1. **A transition that rolls back after its outbox insert** (a later hook error, a lost lease, a crash at `before_commit`) must leave no event: expected, no row without the transition.
2. **Every path to a terminal state** (worker completion, webhook apply, poll, `admin fail`, `admin confirm-step`) must write exactly one event: expected, I8 holds on each, and a second insert for the same workflow fails the transaction.
3. **A client reading another client's workflow, an unknown ID or a malformed ID** must learn nothing: expected, `404 workflow_not_found` for the first two, `400 invalid_workflow_id` for the last, with identical bodies for the 404s.
4. **A provider refusal code with unexpected content** (uppercase, spaces, 200 characters, an error sentence) must never reach the shop raw: expected, `reason` falls back to `charge_failed`.
5. **An upgraded database whose workflows finished before migration 00014** must pass `idem check`: expected, the migration backfills their events from `workflow_view`, and its Down removes everything it added.

### Task 1: Schema: `failure_code`, `outbox`, `workflow_view`, backfill

**Files:**
- Create: `migrations/00014_outbox.sql`
- Create: `internal/store/outbox_test.go`

**Interfaces:**
- Produces (SQL): column `steps.failure_code text NULL`; table `outbox`; function `workflow_view(p_workflow_id uuid) RETURNS text` (the JSON above, `NULL` when the workflow does not exist); function `workflow_event_type(p_status text) RETURNS text` (`workflow.succeeded` / `workflow.failed` / `workflow.compensated`, `NULL` for non-terminal).

`outbox` columns, exactly as spec §5.2: `id uuid PRIMARY KEY` (v7, the event ID shops will deduplicate on), `client_id text NOT NULL`, `workflow_id uuid NOT NULL REFERENCES workflows(id)`, `type text NOT NULL CHECK (type IN ('workflow.succeeded','workflow.failed','workflow.compensated'))`, `payload bytea NOT NULL`, `created_at timestamptz NOT NULL DEFAULT now()`, `status text NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING','DELIVERED','NO_ENDPOINT','DEAD'))`, `attempts int NOT NULL DEFAULT 0`, `next_attempt_at timestamptz NOT NULL DEFAULT now()`, `lease_owner text`, `lease_expires_at timestamptz`, `delivered_at timestamptz`, `last_error text`, `UNIQUE (workflow_id, type)`; index `outbox_due ON outbox (next_attempt_at) WHERE status = 'PENDING'`.

`workflow_view` builds `json_strip_nulls(json_build_object(...))::text` in the key order shown above (`json`, not `jsonb`, keeps the order). Timestamps: `to_char(t AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`. Amounts and currency come from `workflows.input`. The failed reason reads the `failure_code` of the workflow's latest-generation `charge` step in `FAILED_PERMANENT`. Declare it `STABLE`.

Backfill at the end of Up: one `INSERT INTO outbox (id, client_id, workflow_id, type, payload) SELECT gen_random_uuid(), client_id, id, workflow_event_type(status), convert_to(workflow_view(id), 'UTF8') FROM workflows WHERE workflow_event_type(status) IS NOT NULL`. (Backfilled IDs are v4; new ones are v7. Both are valid event IDs.) Down: drop the functions, the table and the column.
