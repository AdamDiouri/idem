# Slice 1.2 — Charge Step End to End — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Workers claim the `charge` step under a lease with a fencing token, charge a fake payment provider with the step's stored idempotency key, and post balanced ledger entries in the same transaction as the success transition. Simulated crashes and pauses (F4–F6, F12, F13) must never produce a second charge or a second ledger posting, and an invariant checker (I1, I2) proves it.

**Architecture:** Every step runs claim → call → complete (design §9.1). Claim and complete are separate Postgres transactions; the provider call happens with no transaction open. Completion is a compare-and-swap on `(id, lease_epoch, status='RUNNING')`, so a worker that lost its lease is rejected (fencing). The provider's idempotency key makes a late or repeated call harmless. A crashed worker's step is recovered by a lease-expiry sweep that moves it to `IN_DOUBT`. The fake provider is the system's adversary *and* its ground truth: it injects faults and records every real effect in an oracle the invariant checker reads.

**Tech Stack:** As slice 1.1 (Go 1.25, pgx/v5, sqlc, goose, testcontainers, testify). New: `math/rand/v2` (failpoint probabilities). No new third-party dependencies.

**Spec:** `docs/design.md` — §4 (GR1, GR2, GR3, GR5, A4), §5, §6, §8.1, §8.3, §9.1, §9.3, §10, §11.1 (first row), §11.2, §12 (F4–F7, F9, F10, F12, F13, F27), §13 (I1, I2), §14.1, §14.2.

## Global Constraints

- Go 1.25, `GOTOOLCHAIN=local`. Any new dependency must support Go 1.25 (see slice 1.1 pins).
- No ORM; all SQL in `.sql` files; regenerate with `make generate` and commit the output.
- Lease and retry times come **only** from Postgres `now()`; never compare worker clocks (A4).
- **Every change of step ownership increments `lease_epoch`** (D7): claim and lease-expiry reclaim.
- Fenced completion predicate is exactly `WHERE id = $id AND lease_epoch = $epoch AND status = 'RUNNING'`; 0 rows ⇒ `engine.ErrFenced`, roll back, write nothing.
- The provider call always uses `steps.idempotency_key` read from the database; never call `workflow.StepIdempotencyKey` for an existing step (D6).
- Ledger amounts are signed `int64` cents (debit `+`, credit `−`), currency `EUR`, no zero-amount entries, every ledger transaction sums to 0.
- Ledger postings are written in the same transaction as the step's success transition (D2).
- Ambiguous provider outcomes become `IN_DOUBT`, never failed (D5).
- Config rule: `provider_timeout + 2s commit budget < lease_ttl`.
- Failpoints compile to no-ops with build tag `nofailpoint`.
- Commit messages: Conventional Commits, **no `Co-Authored-By` or other attribution trailers.**

## Decisions this plan makes (not in the spec)

- **Lease-expiry reclaim is pulled forward from slice 1.3** (`engine.ReclaimExpiredLeases`, design §11.1 row 1 only). F4–F6 and F12 cannot be tested without it. The rest of the sweeper, backoff with jitter, `max_attempts`/`DEAD` and 429/connection-refused refinements stay in 1.3. Until then `IN_DOUBT` retries use a fixed `RetryDelay` with no attempt limit.
- **Workers claim only step names they have handlers for.** After a successful charge the `payout` step is created `PENDING` and simply waits until slice 1.4 adds its handler.
- **Ledger immutability is enforced by triggers**, not DB role grants (works with the compose superuser; `TRUNCATE` in tests still works because row triggers don't fire on it).
- **Accounts are three global rows** (`provider_receivable`, `merchant_payable`, `platform_revenue`), linked to workflows through `ledger_transactions.workflow_id`. Per-merchant accounts can come later.
- **In-process crash simulation:** failpoint `CrashOnce` panics with `failpoint.ErrCrash`; the worker never recovers that panic, so the claim stays committed and any open transaction is rolled back by its deferred `Rollback` — the same observable state as a killed process. Real `exit` crashes (env-configured) are used from slice 1.6.
- **Fake provider deterministic decline:** any `customer_id` starting with `cus_decline` returns `402 card_declined` (like Stripe test cards). Declines are stored against the idempotency key and replayed.
- **Container images keep failpoints compiled in** (inactive unless `IDEM_FAILPOINTS` is set) so slice 1.6 chaos runs can use them; `make build-release` builds with `-tags nofailpoint`.
- **Graceful shutdown:** `Worker.Run` stops claiming when its context is cancelled but finishes the in-flight step on a context detached from cancellation (design §11.2).

## Review Focus

1. **Provider returns 2xx with a different amount or an unparseable body** — must not be recorded as success; it is `Ambiguous` → Task 3 `TestClassify` rows "amount mismatch", "unparseable 2xx".
2. **Completion fails for a non-fencing reason (DB error, hook error)** — the step must stay `RUNNING` for the lease path and the worker loop must keep running → Task 6 `TestComplete_HookErrorRollsBack`, Task 7 `TestWorker_RunSurvivesStepErrors`.
3. **Two sweepers reclaim at the same time** — the epoch must be bumped exactly once → Task 6 `TestReclaim_ConcurrentSweepersBumpOnce`.
4. **A crash after the provider call must not create two `payout` steps or two ledger postings** → Task 7 crash table asserts `payout` step count 1 and ledger transaction count 1.
5. **SIGTERM while a step is mid-flight** must finish that step, not strand it until lease expiry → Task 7 `TestWorker_RunFinishesInFlightStepOnCancel`.

### Task 2: Fake payment provider with fault injection and effects oracle

**Files:**
- Create: `internal/fakeprovider/provider.go`, `internal/fakeprovider/faults.go`, `internal/fakeprovider/client.go`, `cmd/fakeprovider/main.go`
- Test: `internal/fakeprovider/provider_test.go`

**Interfaces:**
- Produces:
  - `fakeprovider.Options{ Hang time.Duration }` — how long timeout faults hang (default `30s`); a hang also ends when the request context is done.
  - `fakeprovider.New(opts Options) *Provider`; `(*Provider).Handler() http.Handler`
  - `(*Provider).SetFaults(f Faults)`, `(*Provider).Effects() []Effect` (copy, in effect order), `(*Provider).Reset()` (keys, effects, faults)
  - `fakeprovider.Faults{ Rules []Rule }`; `fakeprovider.Rule{ Endpoint string \`json:"endpoint"\`; Mode string \`json:"mode"\`; Probability float64 \`json:"probability"\`; Times int \`json:"times"\` }` — `Endpoint` is `"charges"`; `Probability` 0 means 1; `Times` 0 means unlimited, otherwise the rule fires at most `Times` times. First matching rule wins. Seeded RNG: `Faults{Seed int64}` field, default 1.
  - Modes: `timeout_before_effect` (hang, no effect), `timeout_after_effect` (effect + store success, then hang), `error_before_effect` (500, no effect), `error_after_effect` (effect + store success, respond 500), `decline` (402, stored).
  - `fakeprovider.Effect{ ID string \`json:"id"\`; Type string \`json:"type"\`; WorkflowID string \`json:"workflow_id"\`; IdempotencyKey string \`json:"idempotency_key"\`; AmountCents int64 \`json:"amount_cents"\`; At time.Time \`json:"at"\` }` — `Type` is `"charge"`.
  - `fakeprovider.FetchEffects(ctx context.Context, baseURL string) ([]Effect, error)`; `fakeprovider.PutFaults(ctx context.Context, baseURL string, f Faults) error`
- HTTP:
  - `POST /charges` with header `Idempotency-Key`, body `{"amount_cents":int64,"currency":"EUR","customer_id":string,"workflow_id":string}` (unknown fields rejected).
    - `201` `{"id":"ch_<uuidv7>","status":"succeeded","amount_cents":…,"currency":"EUR"}` and one `Effect` recorded.
    - Same key + byte-identical canonical body (re-marshalled struct) → replay stored status + body, **no new effect**.
    - Same key + different body → `422 {"error":{"code":"idempotency_key_reused"}}`.
    - Same key while the first request is still being processed → `409 {"error":{"code":"idempotency_key_in_flight"}}`.
    - `customer_id` prefix `cus_decline` or `decline` fault → `402 {"error":{"code":"card_declined"}}`, stored, no effect.
    - Missing key or invalid body → `400`.
  - `GET /charges?idempotency_key=<k>` → stored status/body if the key has a stored result, else `404`.
  - `PUT /_faults` (JSON `Faults`) → `204`; `GET /_effects` → `200` JSON array; `POST /_reset` → `204`.
- `cmd/fakeprovider`: listens on `FAKEPROVIDER_ADDR` (default `:9090`), `slog` JSON logs, graceful shutdown on SIGTERM.

  - `type engine.Step interface { Name() string; Execute(ctx context.Context, s ClaimedStep) provider.Outcome; OnSuccess(ctx context.Context, q *db.Queries, s ClaimedStep, providerRef string) error; OnPermanentFailure(ctx context.Context, q *db.Queries, s ClaimedStep) error }` — hooks run inside the completion transaction.
  - `var engine.ErrFenced = errors.New("lease lost: completion fenced")`
  - Failpoint name constants: `FPAfterClaim = "after_claim"`, `FPBeforeProviderCall = "before_provider_call"`, `FPAfterProviderCall = "after_provider_call"`, `FPBeforeCommit = "before_commit"`, `FPAfterCommit = "after_commit"`.
- Produces (functions):
  - `engine.Claim(ctx context.Context, pool *pgxpool.Pool, workerID string, names []string, leaseTTL time.Duration) (ClaimedStep, bool, error)` — one transaction: design §9.1 claim CTE extended with `AND name = ANY(@names)`, `first_attempted_at = COALESCE(first_attempted_at, now())`, `lease_expires_at = now() + (@lease_ms::bigint * interval '1 millisecond')`, joined to `workflows` to return `input`; insert `step_attempts(step_id, attempt_no = new attempt_count, lease_epoch, worker_id)`; `UPDATE workflows SET status='RUNNING', version=version+1, updated_at=now() WHERE id=$1 AND status='PENDING'`. Returns `false` when nothing is claimable.
  - `engine.Complete(ctx context.Context, pool *pgxpool.Pool, s ClaimedStep, r Result, step Step) error` — one transaction: fenced `UPDATE steps` (predicate in Global Constraints) setting status = `r.Kind`, `lease_owner = NULL`, `lease_expires_at = NULL`, `provider_ref`, `last_error`, and for `IN_DOUBT` `run_after = now() + RetryDelay`; 0 rows → `ErrFenced`. Then the hook (`OnSuccess` / `OnPermanentFailure`; none for `IN_DOUBT`), then `UPDATE step_attempts SET outcome, http_status, error, finished_at = now() WHERE step_id AND attempt_no AND outcome IS NULL`, then `failpoint.Hit(FPBeforeCommit)`, `COMMIT`, `failpoint.Hit(FPAfterCommit)`. Any error rolls back.
  - `engine.ReclaimExpiredLeases(ctx context.Context, pool *pgxpool.Pool) (int64, error)` — single statement (CTE): `status 'RUNNING' AND lease_expires_at < now()` → `status = 'IN_DOUBT'`, `lease_epoch + 1`, `lease_owner = NULL`, `lease_expires_at = NULL`, `run_after = now()`; and their open attempt rows → `outcome = 'ABANDONED'`, `finished_at = now()`. Returns steps reclaimed.
