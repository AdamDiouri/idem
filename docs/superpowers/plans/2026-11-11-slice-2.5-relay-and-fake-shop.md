# Slice 2.5: Relay and Fake Shop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every workflow outcome in the outbox reaches its shop, signed, at least once, and chaos proves the shop ends up knowing exactly the outcomes idem committed (invariant I9), with the shop and the relays failing on purpose.

**Architecture:** A new process, `idem relay` (package `internal/relay`), claims due `PENDING` outbox rows under a fenced lease, `POST`s the frozen payload to the client's configured URL with an HMAC signature, and records `DELIVERED`, a backoff, `DEAD` or `NO_ENDPOINT`. Operators list and redeliver events with audited admin commands. A fake shop (`internal/fakeshop`, binary `fakeshop`) receives, verifies and deduplicates events, injects faults, and exposes what it learned as the oracle for I9. Chaos runs two relays and the shop, kills relays, and breaks the shop.

**Tech Stack:** Go 1.27.4 (pinned in `go.mod`), Postgres 18, sqlc on pgx/v5, goose, net/http, cobra, caarlos0/env, client_golang.

**Spec:** [M2 design](../specs/2026-11-10-milestone-2-design.md) §5.3, §5.4, §5.5, §8 (F31–F33), §9 (I4, I9), §10 (slice 2.5); [design](../../design.md) §11.3; decisions [D14](../../adr/0014-at-least-once-outbound-delivery.md), [D19](../../adr/0019-outbox-rows-for-every-client.md).

## Global Constraints

- Postgres is the only state store (D1); hand-written SQL through sqlc (D8); `make generate` after query changes. Lease and schedule times come from the database's `now()` (D3); the F24 clock guard must keep passing.
- Every change of an outbox row's owner bumps `lease_epoch`, and a relay's completion is a compare-and-swap on it (D7).
- Signature: the existing scheme, `webhook.Sign` (`t=<unix>,v1=<hex HMAC-SHA256(secret, "<t>.<body>")>`), header `Idem-Signature`, with the client's secret. Event ID header `Idem-Event-Id: <outbox id>`.
- Client configuration is environment-only, set by the operator (never through the API: no SSRF): `IDEM_CLIENT_WEBHOOKS="client=url,..."` and `IDEM_CLIENT_WEBHOOK_SECRETS="client=secret,..."`.
- `IDEM_RELAY_MAX_ATTEMPTS` default `15`. A client with no URL: its rows become `NO_ENDPOINT`, no alert (D19).
- Integration tests run as the restricted login (`testutil.NewPool`); the services cannot delete outbox rows.
- Commits never carry a `Co-Authored-By` line. `make test`, `make lint`, `make vuln`, `make build-release` and the chaos smoke pass; CI is green.

## Decisions for the owner to confirm

1. **Backfilled events are not announced.** Migration 00016 marks events backfilled by 00015 (their IDs are UUIDv4; live events are v7) with a new status, `SKIPPED`, and a `last_error` saying why. Otherwise the first relay would push every historical outcome to shops at once. An operator can still send any of them with `idem admin outbox redeliver`. `SKIPPED` is used for nothing else.
2. **Retry schedule defaults:** `IDEM_RELAY_RETRY_BASE=30s`, `IDEM_RELAY_RETRY_CAP=6h`, full jitter, 15 attempts: on average about 16 hours before `DEAD`, at most about 32 ("roughly a day", spec §5.3).
3. **The fake shop also runs in compose**, as the demo client's webhook receiver, so `make up` shows delivery end to end. A third header, `Idem-Event-Type`, carries the event type (the spec names two headers; a shop can route on the type without parsing the body).
4. **The shop's `down` fault** closes the connection without answering: the relay sees a transport error, as with a crashed shop. Chaos never stops the shop process itself; a refused connection (nothing listening) is covered by a relay unit test against a closed port.

## Review Focus

1. **A relay that pauses past its lease while delivering** (another relay re-claims and delivers): expected, the late relay's completion is fenced (no status change, counted `fenced`), the row ends with one final status, and the shop deduplicates the second delivery.
2. **A shop that answers `2xx` only after the relay's timeout** (`ack_after_timeout`): expected, the relay treats it as a failure and retries; the shop processes the event once.
3. **Misconfigured clients** (a URL without a secret, a secret without a URL, a malformed or non-HTTP URL, a secret under 16 characters, a duplicate client): expected, `idem relay` refuses to start with exit 2 and a message naming the client.
4. **A shop response that redirects or is huge**: expected, the relay never follows a redirect (a `3xx` is a failed attempt, so a shop cannot point idem at another host) and reads at most 4 KiB of any response.
5. **An operator redelivering an event the relay is still working on, or two operators redelivering at once**: expected, a `PENDING` event is refused (`ErrNotActionable`), a changed attempt count is refused (`ErrStale`), exactly one audit row is written.

### Task 3: The relay

**Files:**
- Create: `internal/relay/relay.go`, `internal/relay/relay_test.go`, `internal/store/queries/relay.sql`
- Modify: `internal/metrics/metrics.go`

**Interfaces:**
- Consumes: `lease_epoch`, `SKIPPED` (Task 1); `config.RelayConfig` values (Task 2, passed as `Options`).
- Produces:
  - `relay.Options{ID string; Clients map[string]Endpoint; LeaseTTL, Timeout, PollInterval, ShutdownGrace time.Duration; MaxAttempts int32; Retry engine.Backoff; Metrics *metrics.Metrics; Logger *slog.Logger}` and `relay.Endpoint{URL string; Secret []byte}`.
  - `relay.New(pool *pgxpool.Pool, opts Options) *Relay`; `(*Relay).Run(ctx) error`; `(*Relay).RunOnce(ctx) (Result, error)` with `Result{Claimed bool; EventID uuid.UUID; Outcome string}`.
  - Outcomes (also the `idem_relay_deliveries_total{result}` labels): `delivered`, `retry`, `dead`, `no_endpoint`, `fenced`.
  - Failpoints `relay.FPBeforeSend = "relay_before_send"`, `relay.FPAfterSend = "relay_after_send"`.
  - Queries: `ClaimOutboxEvent(owner, lease_ms)` (due `PENDING`, lease expired or none, `ORDER BY next_attempt_at`, `FOR UPDATE SKIP LOCKED`; sets owner, `lease_epoch + 1`, `attempts + 1`, `lease_expires_at`; returns `id, client_id, workflow_id, type, payload, attempts, lease_epoch`); `FinishOutboxEvent(id, lease_epoch, status, last_error, retry_ms)` (`:execrows`, `WHERE id AND lease_epoch AND status = 'PENDING'`; clears the lease; sets `delivered_at = now()` for `DELIVERED`, `next_attempt_at = now() + retry` for `PENDING`).
  - Metrics: `RelayDeliveries *prometheus.CounterVec` (`idem_relay_deliveries_total{result}`), `RelayDuration prometheus.Histogram` (`idem_relay_delivery_duration_seconds`), with `ObserveRelay(result string, d time.Duration)`.

Behaviour of one delivery: no endpoint for the client → `NO_ENDPOINT` (no request). Otherwise `POST` the payload bytes as-is with `Content-Type: application/json`, `Idem-Event-Id`, `Idem-Event-Type`, `Idem-Signature` (signed at send time); HTTP client with `Timeout`, `CheckRedirect` returning `http.ErrUseLastResponse`, and at most 4 KiB of the response read. `2xx` → `DELIVERED`; anything else, a timeout or a transport error → `DEAD` if `attempts >= MaxAttempts`, else `PENDING` after `Retry.Delay(attempts)` with `last_error` (status code or error, at most 500 bytes). `failpoint.Hit(FPBeforeSend)` before the request, `failpoint.Hit(FPAfterSend)` after the response and before finishing. A completion that updates 0 rows is `fenced`: logged at WARN, nothing else.
