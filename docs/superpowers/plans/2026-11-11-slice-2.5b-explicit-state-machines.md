# Slice 2.5b: Explicit State Machines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make idem's implicit state machines explicit where it buys safety: one definition of "money may have moved", workflow and step transitions enforced by the database, the outbox requeue guarded in SQL, the fake provider's delivery lifecycle as one state, and the design doc's state tables matching the code.

**Architecture:** Two row triggers (`BEFORE UPDATE OF status`) reject any workflow or step status change not in an allowed-edges table defined in SQL, the same way the ledger and outbox rules are enforced (D21, D13). "Terminal" and "active" workflow statuses become SQL functions reused by every query. In Go, `ClaimedStep.MoneyMayHaveMoved()` replaces four hand-written checks. Test fixtures that plant arbitrary states go through one helper that bypasses triggers as the owner.

**Tech Stack:** Go 1.27.4, Postgres 18, sqlc on pgx/v5, goose.

**Spec:** the external review of implicit state machines (2026-11-11, summarised in the PR), [design](../../design.md) §8.2, §8.3, §11.3; [M2 design](../specs/2026-11-10-milestone-2-design.md) §4.4; decisions D5, D7, D13, D21.

## Global Constraints

- No behaviour change for any legal path: the full suite and chaos campaigns pass unchanged in their assertions.
- Triggers raise SQLSTATE `23514` with a message naming the row, the old and the new status.
- Same-status updates are always allowed (the `RUNNING → RUNNING` guard in `chargeStep.OnSuccess`).
- Only `UPDATE OF status` is checked; inserts are not (only `Submit` and `newStepGeneration` insert, always `PENDING`).
- The services never bypass a trigger. Only test fixtures may, as the owner, through `testutil.Plant`.
- Commits never carry a `Co-Authored-By` line; `make test`, `make lint`, `make vuln`, chaos smoke green; CI green.

## The transition tables (the decisions this plan makes)

Workflows (`workflow_transition_allowed(from, to)`):

| From | To |
|---|---|
| `PENDING` | `RUNNING` |
| `RUNNING` | `SUCCEEDED`, `FAILED`, `COMPENSATING`, `NEEDS_ATTENTION` |
| `COMPENSATING` | `COMPENSATED`, `NEEDS_ATTENTION` |
| `NEEDS_ATTENTION` | `RUNNING`, `COMPENSATING`, `FAILED` |
| any | itself |

Steps (`step_transition_allowed(from, to)`):

| From | To | Writer |
|---|---|---|
| `PENDING`, `IN_DOUBT`, `AWAITING_CALLBACK` | `RUNNING` | `ClaimStep` |
| `RUNNING` | `PENDING`, `IN_DOUBT`, `AWAITING_CALLBACK`, `SUCCEEDED`, `FAILED_PERMANENT`, `DEAD` | `CompleteStep`, `ReclaimExpiredLeases`, hook failures |
| `AWAITING_CALLBACK` | `SUCCEEDED`, `FAILED_PERMANENT`, `DEAD` | `ApplyCallbackToStep` (webhook, no lease) |
| `DEAD`, `FAILED_PERMANENT` | `PENDING`, `IN_DOUBT`, `SUCCEEDED` | `ResetStepForRetry`, `ConfirmStepSucceeded` (admin) |
| any | itself | |

`SUCCEEDED` has no way out. Terminal workflow statuses: `SUCCEEDED`, `FAILED`, `COMPENSATED`. Active: `PENDING`, `RUNNING`, `COMPENSATING`.

## Review Focus

1. **A legal path the tables forget** (admin `new-generation`, `confirm-step` on a refused refund, `compensate`, a hook failure from `COMPENSATING`, the webhook shortcut, lease reclaim of a poll): expected, every existing path still works. The executor greps every `UPDATE … status` writer in `internal/store/queries/` and maps it to a table row before writing the trigger.
2. **Same-status writes** (`RUNNING → RUNNING`, a reclaim that leaves `AWAITING_CALLBACK`): expected, allowed.
3. **An upgraded database** with rows in any state: expected, the migration succeeds (triggers check transitions, not existing rows) and its Down removes everything it added.
4. **The "money may have moved" readers**: expected, every Go reader uses the one predicate, and the Go predicate agrees with the SQL `step_send_doubt` + status view used by the admin commands for every combination of prior status and attempt history.
5. **Chaos with a target down**: expected, a kill or pause whose target worker is restarting goes to another running worker, and is skipped only when none runs.
