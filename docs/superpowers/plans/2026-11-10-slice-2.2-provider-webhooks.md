# Slice 2.2: Provider Webhooks — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The provider tells idem a payout's result by signed webhook. idem stores each webhook durably before acknowledging it, applies it through the same compare-and-swap path as a poll, and never lets a late or contradictory webhook flip a decided result. Polling (slice 2.1) stays as the safety net.

**Architecture:**
- **New package `internal/webhook`** signs and verifies (Stripe's `t=…,v1=…` HMAC scheme) and defines the event type. Both the fake provider and the API use it.
- **The API** stores verified events in `webhook_inbox` and answers `200`.
- **A new `InboxProcessor` in the engine,** run by the worker process next to the step loop, claims inbox rows under a lease. It applies an event to an `AWAITING_CALLBACK` step in one transaction, using the same hooks as a worker completion.
- **When the news disagrees with what idem already decided, or the step is parked,** it first re-checks the provider with `GET /payouts/{id}`. It then records the event as stale, as evidence, or as a real conflict.

**Tech Stack:** Go 1.25, Postgres 18, sqlc v1.30.0 (`sqlc.arg`), goose, pgx/v5, testcontainers, testify, `crypto/hmac`.

**Spec:** `docs/superpowers/specs/2026-11-10-milestone-2-design.md` §4.1 (webhooks, faults), §4.3, §4.4 (including D16, D18), §4.6, §8 (F15–F17, F19, F28–F30), §9 (I4, I10), §10 (slice 2.2). M1 spec: `docs/design.md`.

## Global Constraints

- Go 1.25 with `GOTOOLCHAIN=local`; standard library crypto only, no new dependencies.
- sqlc queries use `sqlc.arg(...)`; regenerate with `make generate`.
- **Durable before acknowledged:** `POST /webhooks/provider` answers `2xx` only after the inbox row is committed. Duplicates also get `200`; a store failure gets `503`.
- **Signatures:** header `Idem-Provider-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, "<t>.<raw body>")>`, compared in constant time. Reject if `|now − t| > 5m`. Secrets come from `IDEM_PROVIDER_WEBHOOK_SECRETS` (comma-separated: current first, then previous, for rotation). With no secret configured, the endpoint is off (`404`).
- **Body limit** is 64 KiB. The inbox stores the raw body byte-exact (`bytea`).
- **Never flip a terminal state** (D16).
- **A parked step leaves `NEEDS_ATTENTION` only through a human:** news about it is recorded as evidence (D18).
- **Ledger posting and outcome commit in one transaction** (D2). Every webhook application bumps `lease_epoch` and is fenced by a compare-and-swap on `status = 'AWAITING_CALLBACK'`.
- Commits never carry a `Co-Authored-By` line. `make test`, `make lint` and `make build-release` pass at the end of every task.

## Review Focus

1. **A webhook that arrives while a poll of the same payout is in flight** (the step is `RUNNING`) must be deferred, then become a no-op once the poll lands: exactly one ledger posting (F30). Test: Task 4 `TestInbox_WebhookDuringPollIsDeferredThenNoop`.
2. **Secret rotation:** a webhook signed with the *previous* secret must be accepted, and one signed with neither must be refused with nothing stored. Test: Task 3 `TestWebhooks_AcceptsPreviousSecret`.
3. **A replay:** a correctly signed webhook whose timestamp is more than 5 minutes old must be refused with nothing stored (F19). Test: Task 3 `TestWebhooks_RejectsStaleTimestamp`.
4. **An event for a payout idem never recorded** must end `IGNORED` (orphan) after `OrphanAfter`, not be retried forever or crash the loop. Test: Task 4 `TestInbox_OrphanIgnoredAfterThreshold`.
5. **An operator acting while the processor re-checks the provider** (the step changed between the re-check and the apply) must make the processor defer and re-evaluate, never act on the old state. Test: Task 4 `TestInbox_StateChangedDuringRecheckDefers`.

### Task 2: Fake provider — active settlement, signed webhooks, retries and faults

**Files:**
- Modify: `internal/fakeprovider/provider.go`, `internal/fakeprovider/faults.go`, `cmd/fakeprovider/main.go`
- Create: `internal/fakeprovider/webhooks.go`
- Test: `internal/fakeprovider/webhooks_test.go`

**Interfaces:**
- Consumes: Task 1 (`webhook.Sign`, `webhook.ProviderEvent`, the event constants).
- Produces:
  - **Options:**
    - `WebhookURL string`, `WebhookSecret []byte`
    - `WebhookRetryBase time.Duration` (default 1s)
    - `WebhookMaxAttempts int` (default 8)
    - `Tick time.Duration` (default 50ms)
  - **`func (p *Provider) Run(ctx context.Context)`:** until `ctx` ends, every `Tick` it settles due payouts and delivers queued webhook events. Without `Run`, settlement stays lazy, exactly as in 2.1, so every existing test is unchanged.
  - **Events:** settling a payout enqueues an event (`evt_<uuidv7>`, type `payout.paid` or `payout.failed`, `created` = the settlement time) when `WebhookURL` is set.
  - **Delivery:**
    - `POST` with the JSON body, the signature header, a 2s timeout
    - `2xx` → delivered
    - anything else → retry after `WebhookRetryBase·2^n`, up to `WebhookMaxAttempts` attempts, then give up
  - **Fault endpoint `"webhooks"`.** Its modes:
    - `dup_webhook`: deliver the event twice (both sends follow the normal delivery rules)
    - `fast_webhook`: the payout settles paid at once, and its webhook is delivered synchronously *before* `POST /payouts` writes its `202`
    - `delay_webhook`: first delivery after `4·WebhookRetryBase`
    - `reorder`: after the real event is delivered, also send a stale contradictory one (the opposite type, a new id, `created` = real − 1)
    - `drop_webhook`: never sent
    - `bad_signature`: the first attempt has a wrong signature, later retries are correct
  - Webhook modes are valid only on endpoint `"webhooks"`, and charge/payout modes are invalid there. `pickFault("webhooks")` is drawn once per event, and the hit is counted in `FaultHits` as `webhooks/<mode>`.
  - **`GET /_webhooks`** and `(*Provider).Webhooks() []WebhookDelivery`, where `WebhookDelivery{EventID, Type, PayoutID string; Attempts int; Delivered, Stale bool; Fault string}`. This is the oracle for I10.
  - **`cmd/fakeprovider`:** reads `FAKEPROVIDER_WEBHOOK_URL` and `FAKEPROVIDER_WEBHOOK_SECRET`, and starts `Run`.

### Task 4: The inbox processor — apply, defer, re-check, evidence, conflict

**Files:**
- Create: `internal/engine/inbox.go`
- Modify: `internal/store/queries/inbox.sql`, `internal/engine/complete.go`
- Test: `internal/engine/inbox_test.go`

**Interfaces:**
- Consumes: Tasks 1–3; slice 2.1's `decidePoll`, `Poller`, `Step` hooks, `transitionWorkflow`.
- Produces:
  - **The processor:**
    - `type InboxOptions struct { ID string; Steps []Step; LeaseTTL, PollInterval, OrphanAfter time.Duration; Retry Backoff; Metrics *metrics.Metrics; Logger *slog.Logger }`
    - `func NewInboxProcessor(pool *pgxpool.Pool, opts InboxOptions) *InboxProcessor`
    - `func (p *InboxProcessor) RunOnce(ctx context.Context) (InboxResult, error)` and `func (p *InboxProcessor) Run(ctx context.Context) error`
    - `type InboxResult struct { Claimed bool; EventID string; Outcome string }`
  - **Outcomes:** `applied`, `noop`, `deferred`, `orphaned`, `stale`, `evidence`, `conflict`, `malformed`. Metric `idem_webhooks_applied_total{outcome}` via `ObserveInbox(outcome string)`.
  - **Failpoint:** `const FPInboxBeforeCommit = "inbox_before_commit"`, added to `FailpointNames`.
  - **Refactor:** `Complete`'s result handling after the compare-and-swap (the hook `switch`) is extracted into `applyResult(ctx, q, s ClaimedStep, r Result, step Step) error`. Both `Complete` and the inbox call it.
  - **Queries:**
    - **`ClaimInboxEvent`:** the next `PENDING` row with `next_attempt_at <= now()` and no live lease, `FOR UPDATE SKIP LOCKED`. It sets the lease (owner, `lease_epoch + 1`, expiry) and `attempts + 1`, and returns the row.
    - **`StepForEvent`:** a snapshot of the step matching `provider_ref = $payout_id`, or else `idempotency_key = $key`, newest generation first. It returns the step fields `Claim` returns, plus `status`, `dead_reason`, the workflow status, `send_doubt`, whether it is the workflow's newest step, and `input`.
    - **`LockStepForEvent`:** the same row `FOR UPDATE OF s, w`.
    - **`ApplyCallbackToStep :execrows`:** sets `status`, `provider_ref` (coalesced), `dead_reason`, `last_error`, `lease_epoch + 1`, `poll_count + 1` (the counter for non-send attempt numbers), `callback_deadline = NULL`, `WHERE id AND status = 'AWAITING_CALLBACK'`.
    - **`InsertStepAttempt`** with kind `webhook`, finished with the outcome.
    - **`FinishInboxEvent :execrows`:** sets `status`, `note`, `step_id`, `processed_at`, clears the lease, `WHERE provider_event_id AND lease_epoch = $epoch`. Zero rows means fenced: roll back.
    - **`DeferInboxEvent :execrows`:** `next_attempt_at = now() + delay`, `last_error`, lease cleared, fenced the same way.

**Decision table** (the algorithm the tests pin). Phase 1 claims the row (committed lease). Phase 2 reads `StepForEvent` and decides whether a provider re-check (`Poll`, outside any transaction) is needed. Phase 3 runs one transaction: `LockStepForEvent`, re-evaluate, write, `FinishInboxEvent` or `DeferInboxEvent`. If the locked state differs from phase 2's snapshot (status, `dead_reason`, workflow status, or newest step), defer by `Retry.Base` with `last_error "state changed during re-check"`.

| Step state at apply | Event | Re-check? | Result |
|---|---|---|---|
| no matching step, received < `OrphanAfter` ago | any | no | `deferred` (backoff `Retry.Delay(attempts)`) |
| no matching step, received ≥ `OrphanAfter` ago | any | no | row `IGNORED`, note `orphan`; `orphaned` |
| `PENDING` / `RUNNING` / `IN_DOUBT` (the webhook beat our commit, or a poll is in flight) | any | no | `deferred` (F16, F30) |
| `AWAITING_CALLBACK` | paid / failed | no | the outcome from `decidePoll` (with the event as the Outcome and zero limits), then `applyResult`; attempt kind `webhook`; row `PROCESSED`; `applied` |
| `SUCCEEDED` with paid, or `FAILED_PERMANENT` with failed | same | no | row `PROCESSED`, note `duplicate`; `noop` |
| `SUCCEEDED` with failed, or `FAILED_PERMANENT` with paid | different | **yes** | the provider's current status equals idem's: `IGNORED`, note `stale`; otherwise `CONFLICT`, note `provider says <status>, idem recorded <…>` |
| `DEAD`, workflow `NEEDS_ATTENTION`, newest step | any | **yes** | row `EVIDENCE`, note `provider says paid <po_…>` or `provider says failed: <code>`; `evidence`. The workflow stays parked (D18). |
| `DEAD`, the operator already acted (workflow not `NEEDS_ATTENTION`, or not the newest step) | any | **yes** | idem's belief is "not paid". The provider says paid → `CONFLICT`; failed → `PROCESSED`, note `agrees with operator` |
| any re-check that is `Pending` or fails | — | — | `deferred` |
| payload not a valid `ProviderEvent` | — | no | `IGNORED`, note `malformed`; `malformed` |
