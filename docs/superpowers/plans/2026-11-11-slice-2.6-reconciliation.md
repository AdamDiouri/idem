# Slice 2.6: Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A job, `idem reconcile`, compares the provider's own record of money movements with idem's ledger and steps, records every difference with its kind, and changes nothing else (D15); chaos requires zero differences outside parked workflows, and that parked ones are reported exactly.

**Architecture:** The fake provider gains a production-style, paginated report of balance transactions (one row per money movement, signed, with workflow metadata). A new package `internal/recon` fetches the report for a window, loads the ledger postings and step states of every workflow touched in that window, classifies each difference with a pure function, and stores the run in two new tables. The sweeper exports the latest run as gauges, two alerts watch them, `idem admin` shows them (next to parked workflows as evidence), compose runs the job every 10 minutes, and chaos runs it over each campaign.

**Tech Stack:** Go 1.27.4, Postgres 18, sqlc on pgx/v5, goose, cobra, client_golang.

**Spec:** [M2 design](../specs/2026-11-10-milestone-2-design.md) §6 (Part C), §8 (F34), §9 (Recon), §10 (slice 2.6); [D15](../../adr/0015-reconciliation-only-reports.md).

## Global Constraints

- The job **changes nothing** but its own tables (D15). It reads the provider's report, never the test oracle (`/_effects`).
- Not-yet-final work is never a discrepancy: a workflow with any step `PENDING`, `RUNNING`, `IN_DOUBT` or `AWAITING_CALLBACK` is skipped and counted `in_flight`.
- Parked workflows (`NEEDS_ATTENTION`) are reported, not skipped, and flagged `parked`.
- Kinds: `missing_in_ledger`, `missing_at_provider`, `amount_mismatch`, `duplicate_effect`, `status_mismatch`.
- Default window: the last complete hour ending `IDEM_RECON_LAG` (default `5m`) ago.
- Commits never carry a `Co-Authored-By` line; `make test`, `make lint`, `make vuln`, `make build-release`, chaos smoke pass; CI green.

## Decisions the spec leaves open (this plan's calls)

1. **What is compared.** For each workflow and effect type (charge, payout, refund): the provider's records against idem's postings, where a posting's amount is its `provider_receivable` entry (charge `+amount`, payout `−(amount − fee)`, refund `−amount`), which is exactly the provider's signed amount.
2. **One kind per (workflow, type), by precedence:** `duplicate_effect` (more than one provider record, or more than one posting) > `amount_mismatch` (one each, amounts differ) > `status_mismatch` (a provider record, no posting, and idem recorded that step `FAILED_PERMANENT`: it believes the provider definitely refused) > `missing_in_ledger` (a provider record, no posting) > `missing_at_provider` (a posting, no provider record). A provider record whose `workflow_id` idem does not know is `missing_in_ledger` with no workflow.
3. **Time.** A movement and its posting are not simultaneous (a payout settles, the webhook arrives later). The window decides *which workflows* are reconciled: those with a provider record created in it, or a posting created in it. Each one is then compared on everything known about it: the provider report is fetched for the window widened by `IDEM_RECON_MARGIN` (default `1h`) on both sides.
4. **Metrics come from the sweeper** (the job is short-lived and is not scraped): `idem_reconciliation_discrepancies{kind,parked}` from the latest successful run, and `idem_reconciliation_last_success_timestamp_seconds`.
5. **Compose runs it in a loop** with `idem reconcile --every 10m` (the image has no shell).

## Review Focus

1. **A payout that settled at the end of the window and was posted after it**: expected, no discrepancy (the margin covers it), and none for a workflow still waiting.
2. **A provider report with several pages, or empty**: expected, every page is read (a `has_more` loop with `starting_after`); an empty report with postings in the window yields `missing_at_provider` for each.
3. **The provider unreachable or answering garbage mid-run**: expected, the run ends `FAILED` with its error, writes no discrepancies, and the staleness gauge does not move; nothing else changes.
4. **Two reconciles running at once** (compose loop plus an operator's manual run): expected, both complete with their own run rows; neither blocks workers (read-only on engine tables).
5. **A parked workflow whose ledger is truly behind the provider** (money moved, never posted): expected, reported `missing_in_ledger` with `parked = true`, shown next to it in `idem admin list`, and the drift alert does not page for it (the parked alert already does).

### Task 3: The reconciliation itself

**Files:**
- Create: `internal/recon/classify.go`, `internal/recon/classify_test.go`, `internal/recon/recon.go`, `internal/recon/recon_test.go`, `internal/store/queries/recon.sql`

**Interfaces:**
- Consumes: `provider.BalanceTransaction`, `ListBalanceTransactions` (Task 1); the tables (Task 2).
- Produces:
  - `recon.Workflow{ID uuid.UUID; Status string; StepStatus map[string]string /* effect type → latest step status */; Postings map[string][]int64 /* type → provider_receivable amounts */}`.
  - `recon.Discrepancy{WorkflowID *uuid.UUID; Kind, EffectType string; ProviderRefs []string; ProviderAmount, LedgerAmount *int64; Parked bool; Detail string}`.
  - `recon.Classify(w *Workflow, records []provider.BalanceTransaction) []Discrepancy`: pure, the precedence of decision 2; `w == nil` means the provider named a workflow idem does not know.
  - `recon.Options{Margin time.Duration; Logger *slog.Logger}`; `recon.Run(ctx, pool, client, from, to time.Time, opts) (Result, error)` with `Result{RunID uuid.UUID; Records, Workflows, InFlight, Discrepancies int}`: inserts a `RUNNING` run, fetches the report for `[from − Margin, to + Margin)`, selects the workflows anchored in `[from, to)` (decision 3), skips in-flight ones, classifies the rest, writes the discrepancies and finishes the run `SUCCEEDED` in one transaction; on any error finishes it `FAILED` with the error and writes no discrepancy.
  - Queries: `InsertReconRun`, `FinishReconRun`, `ReconWorkflows(ids)` (status, latest step status per name, postings' `provider_receivable` amounts per kind), `WorkflowsPostedBetween(from, to)`, `InsertReconDiscrepancy`.

**Interfaces:**
- `config.ReconConfig`: `IDEM_DATABASE_URL` (required), `IDEM_PROVIDER_URL` (required), `IDEM_PROVIDER_TIMEOUT` (`10s`), `IDEM_RECON_LAG` (`5m`), `IDEM_RECON_MARGIN` (`1h`), `IDEM_LOG_LEVEL`.
- `idem reconcile [--from RFC3339 --to RFC3339] [--every DURATION]`: without a window, the last complete hour ending `IDEM_RECON_LAG` ago; `--from`/`--to` together or not at all (else exit 2); `--every` repeats until SIGTERM (each run its own window).
