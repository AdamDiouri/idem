# Slice 1.5 — Chaos Harness — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `chaos` program that runs the real system as separate OS processes (Postgres, fake provider, API, several workers and sweepers). Misbehaving clients push traffic through it while the harness kills, freezes and restarts processes, restarts the database, flips provider faults and arms crash failpoints. Then it lets the system settle and delivers a verdict: every invariant (I1–I7) holds and every workflow reached a final or attention state. A seed reproduces the fault plan. The slice also adds the pivot safety rule we agreed for the payout.

**Architecture:**
- **Library:** `internal/chaos` holds the parts:
  - a seeded fault-plan generator (pure)
  - a process supervisor that restarts crashed children, like Kubernetes would
  - a Postgres container controller using the `docker` CLI
  - misbehaving HTTP clients
  - an orchestrator and a report
- **Binary:** `cmd/chaos` wires them together. Children are the real binaries built by `make build`, configured with short leases and retries so a campaign of a minute or two exercises many recoveries.
- **Fault modes covered:**
  - F12/F13 via `SIGSTOP`/`SIGCONT` beyond the lease
  - F14 via a database restart
  - F26 via SIGTERM / restart of the API and workers
  - F4–F6 via `exit` failpoints in real processes

**Tech Stack:** Go 1.25 standard library (`os/exec`, `syscall` signals), the existing packages, and Docker for Postgres. No new dependencies.

**Spec:** `docs/design.md` — §5, §6 (fault model), §12 (F12–F14, F26), §13 (I1–I7), §14.2, §14.3 (chaos runs), §15 row 1.5.

## Global Constraints

- Earlier slice constraints all hold (Go 1.25 pins, `GOTOOLCHAIN=local`, no attribution trailers).
- Linux-only harness (signals, `docker` CLI); it must fail fast with a clear message if `docker` or the binaries are missing.
- **Nothing outside the harness's own resources is touched:**
  - its Postgres container is named `idem-chaos-<seed>` and always removed at the end, even on failure or Ctrl-C
  - it binds only `127.0.0.1` ports it picked as free
  - run artifacts go to `chaos-runs/<timestamp>-seed<seed>/` (git-ignored)
- **Reproducibility:** the *fault plan* (what happens, to which process, when) is a pure function of `(seed, duration, workers)`. OS scheduling is not reproducible; the report says so.
- **Child configuration for chaos:**

  | Variable | Value |
  |---|---|
  | `IDEM_LEASE_TTL` | `4s` |
  | `IDEM_PROVIDER_TIMEOUT` | `1s` |
  | `IDEM_SHUTDOWN_GRACE` | `3s` |
  | `IDEM_RETRY_BASE` | `100ms` |
  | `IDEM_RETRY_CAP` | `2s` |
  | `IDEM_SWEEP_INTERVAL` | `500ms` |
  | `IDEM_POLL_INTERVAL` | `50ms` |

  These satisfy the config rules: timeout + 2s < lease, and grace ≥ timeout + 2s.
- **Exit codes:**
  - `0`: zero violations and liveness holds
  - `1`: violations, or liveness timed out
  - `2`: harness or setup error

## Decisions this plan makes (not in the spec)

- **Pivot safety rule (agreed with the user).** A step whose `Pivot()` is true (payout) that gets a `Permanent` answer when its `PriorStatus` is `IN_DOUBT` goes `DEAD` with the new reason `permanent_after_in_doubt`, so the workflow is `NEEDS_ATTENTION` and no refund is created. A real provider could answer a retry with a 4xx even though an earlier attempt paid the merchant. This keeps the pivot "stuck and loud" instead of "refund and maybe lose the money". Charge and refund are not pivots and are unchanged.
- **I4 (liveness)** is a separate `invariants.CheckLiveness`. It only makes sense after quiescence (no traffic, no faults), whereas `Check` is safe to run at any time. It reports every workflow still in `PENDING`/`RUNNING`/`COMPENSATING`.
- **I6 joins `Check`:** every inbound idempotency key has a workflow and a stored response, and every workflow has exactly one key.
- **The fake provider is never killed.** It is the oracle; its in-memory state must survive (fault model §6). Everything else may be killed.
- **A supervisor restarts any child that exits unexpectedly** after `500ms`. Real `exit` failpoints therefore behave like a Kubernetes pod restart.

## Review Focus

1. **The harness must clean up after itself.** A failed or interrupted run must not leave a Postgres container, a frozen (`SIGSTOP`ped) process or an orphan child behind → Task 4 `TestSupervisor_StopAllResumesAndKills`, Task 6 smoke with Ctrl-C.
2. **A "pass" must not be vacuous.** A run where nothing happened (no workflows, no faults fired) must not report success → Task 6 `TestReport_VacuousRunFails`.
3. **Client retries with the same key must never create two workflows**, even across API restarts and database restarts → Task 5 `TestClients_RetriesConvergeOnOneWorkflow` + I6.
4. **A permanent payout answer after an ambiguous attempt must park the workflow, not refund** → Task 1 `TestFlow_PermanentPayoutAfterDoubtParks`.
5. **Liveness must fail loudly** if the system doesn't settle within the timeout, listing the stuck workflows → Task 2 `TestCheckLiveness_ReportsStuck`.

### Task 3: Seeded fault plan

**Files:** Create `internal/chaos/plan.go`; Test `internal/chaos/plan_test.go`.

**Interfaces — Produces:**
- `chaos.EventKind` string constants:
  - `KillWorker` (SIGKILL; the supervisor restarts it)
  - `PauseWorker` (SIGSTOP for `Duration`, then SIGCONT)
  - `RestartAPI` (SIGTERM, then restart)
  - `RestartPostgres` (`docker restart`)
  - `SetProviderFaults` (`Faults` payload)
  - `ClearProviderFaults`
- `chaos.Event{ At time.Duration; Kind EventKind; Target int /* worker index */; Duration time.Duration; Faults fakeprovider.Faults }`
- `chaos.PlanConfig{ Seed int64; Duration time.Duration; Workers int; LeaseTTL time.Duration }`
- `chaos.NewPlan(cfg PlanConfig) []Event`: deterministic for a given config and sorted by `At`. Rules:
  - one event roughly every 3s on average (exponential gaps from the seeded RNG)
  - kinds weighted Kill 30%, Pause 20%, ProviderFaults 25%, RestartAPI 10%, RestartPostgres 10%, ClearFaults 5%
  - pauses last `LeaseTTL × 1.5–2.5`, so the lease always expires during the pause
  - provider faults are drawn from every mode valid for each endpoint, at probability 0.1–0.4
  - no event in the last 10% of the duration
  - at least one event of each kind when `Duration ≥ 60s`

### Task 4: Process supervisor and Postgres controller

**Files:** Create `internal/chaos/supervisor.go`, `internal/chaos/postgres.go`; Tests `internal/chaos/supervisor_test.go`, `internal/chaos/postgres_test.go`.

**Interfaces — Produces:**
- `chaos.ProcSpec{ Name, Path string; Args, Env []string; LogPath string }`
- `chaos.NewSupervisor(logger *slog.Logger) *Supervisor`
- `(*Supervisor).Start(spec ProcSpec) (*Proc, error)`: starts the child in its own process group, with stdout/stderr appended to `LogPath`. If the child exits while not being deliberately stopped, it is restarted after `500ms` and `Restarts()` increments.
- `(*Proc).Kill() error` (SIGKILL; the supervisor restarts it); `Pause() error` / `Resume() error` (SIGSTOP / SIGCONT); `Restart(ctx) error` (SIGTERM, wait up to 10s, then SIGKILL, then start again); `Restarts() int`; `Name() string`.
- `(*Supervisor).StopAll(ctx) error`: resumes every paused process first (a stopped process cannot handle SIGTERM), sends SIGTERM to each, then SIGKILL after 5s; it waits for every process and disables restarts. Safe to call twice.
- `chaos.Postgres{ Name string; Port int }`; `chaos.StartPostgres(ctx, name string, port int) (*Postgres, error)` runs `docker run -d --name <name> -p 127.0.0.1:<port>:5432 -e POSTGRES_PASSWORD=… postgres:18` and waits for `pg_isready`. `(*Postgres).DSN() string`; `Restart(ctx) error` (`docker restart`, then wait for ready); `Remove(ctx) error` (`docker rm -f`; idempotent).
- `chaos.FreePort() (int, error)`.

Tests use the re-exec helper pattern: when `os.Getenv("CHAOS_HELPER") == "sleep"`, `TestMain` makes the test binary act as a long-running child that writes a heartbeat line every 50ms.

### Task 5: Misbehaving clients

**Files:** Create `internal/chaos/clients.go`; Test `internal/chaos/clients_test.go` (in-process API over `testutil` Postgres, as in `internal/api` e2e tests).

**Interfaces — Produces:**
- `chaos.Behavior` constants:
  - `Polite`: one request, retried on any error until success, same key
  - `Impatient`: client timeout 50–300ms, retries with the same key
  - `DoubleClick`: two concurrent submissions with the same key
  - `Reformatted`: retry with reordered JSON, same key
  - `Malformed`: invalid body, expects 4xx and never retries
- `chaos.ClientConfig{ BaseURL, Token string; Workflows int; Concurrency int; Seed int64 }`
- `chaos.RunClients(ctx, cfg ClientConfig) ClientResult`:
  - Each workflow picks a behavior (Polite 40%, Impatient 25%, DoubleClick 15%, Reformatted 10%, Malformed 10%), a customer (5% `cus_decline_*`) and a merchant (10% `mer_invalid_*`) from the seeded RNG.
  - Retries back off 50ms → 1s with no attempt limit, until `ctx` ends.
  - Every 2xx response for a key must carry the same `workflow_id`.
- `chaos.ClientResult{ Submitted int; Accepted map[string]string /* key → workflow_id */; Rejected int /* malformed, as expected */; Conflicts []string /* keys that saw two workflow IDs */; Unfinished []string /* keys never accepted before ctx ended */; Behaviors map[Behavior]int }`

### Task 6: Orchestrator, report and `cmd/chaos`

**Files:** Create `internal/chaos/run.go`, `internal/chaos/report.go`, `cmd/chaos/main.go`; Tests `internal/chaos/report_test.go`, `internal/chaos/run_test.go` (build tag `chaos`); Modify `Makefile`, `.gitignore`, `README.md`, `docs/design.md`.

**Interfaces — Produces:**
- `chaos.Config{ Seed int64; Duration, SettleTimeout time.Duration; Workflows, Workers, Sweepers int; BinDir, RunDir string; Failpoints string }`. Defaults: 90s duration, 120s settle timeout, 300 workflows, 4 workers, 2 sweepers, `BinDir ./bin`, failpoints `after_claim=exit@0.01,after_provider_call=exit@0.02,before_commit=exit@0.02`.
- `chaos.Run(ctx, cfg Config, logger) (Report, error)`:
  1. Postgres container, then `idem migrate`, the fake provider, the API, workers (with failpoints) and sweepers under the supervisor.
  2. Clients and the fault plan run concurrently for `Duration`. Every executed event is recorded with its wall-clock time.
  3. **Settle:**
     - clear provider faults
     - resume paused workers
     - restart workers *without* failpoints
     - wait until `CheckLiveness` is empty, or `SettleTimeout` elapses
  4. **Verdict:** `invariants.Check` (with effects from the oracle), `CheckLiveness`, the clients' `Conflicts` and `Unfinished`.
  5. Always: `StopAll`, then `Remove` the container. Write `report.json` and `report.txt` to `RunDir`.
- `chaos.Report`:
  - `Seed`, `Config`, `Events []ExecutedEvent`, `Clients ClientResult`
  - `Outcomes map[string]int` (workflow status → count), `NeedsAttention []string`, `Violations []invariants.Violation`
  - `Restarts map[string]int` (process → crash restarts), `SettleTime time.Duration`
  - `Passed bool`, `Reasons []string`
- `Passed` requires all of:
  - zero violations
  - liveness empty
  - no client conflicts and no unfinished keys
  - **non-vacuous**: at least 1 accepted workflow, at least 1 executed fault event, and at least 1 crash restart or pause
- `cmd/chaos`: flags `--seed` (default: time-based, printed), `--duration`, `--settle-timeout`, `--workflows`, `--workers`, `--sweepers`, `--bin-dir`, `--out`. Prints `report.txt` and exits `0`/`1`/`2`. Ctrl-C cancels, and cleanup still runs.
- Makefile: `build` also builds `bin/fakeprovider` and `bin/chaos`; new target `chaos: build` runs `bin/chaos $(CHAOS_ARGS)`.
- `.gitignore`: `chaos-runs/`.
