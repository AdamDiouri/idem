# Slice 1.1 — Skeleton & Idempotent Workflow Submission — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable `idem` binary with Postgres migrations and an idempotent `POST /workflows` endpoint that creates a `payment_payout` workflow plus its first `charge` step, proven against failure modes F1–F3.

**Architecture:** Hand-written SQL (sqlc-generated Go on pgx/v5) against Postgres 18. The HTTP layer (`internal/api`) parses, authenticates and validates; the domain layer (`internal/workflow`) owns the single transaction that inserts the idempotency-key row, workflow row, first step row and stored response together. Concurrent duplicates are serialised by Postgres's unique-index wait — no application locks.

**Tech Stack:** Go 1.25, Postgres 18, `jackc/pgx/v5`, `sqlc`, `pressly/goose/v3`, `spf13/cobra`, `caarlos0/env/v11`, `log/slog`, `google/uuid` (v7), `testcontainers-go` (postgres module), `stretchr/testify/require`, `golangci-lint` v2.

**Spec:** `docs/design.md` (§3 goals, §5 principles, §8.2–8.3 states, §9.2 inbound keys, §10 fees/currency, §12 F1–F3, §13 I6, §7 tech stack)

## Global Constraints

- Module path: `github.com/AdamDiouri/idem`; `go 1.25` in `go.mod`.
- Postgres image `postgres:18` everywhere (compose and tests). PG18 images store data under `/var/lib/postgresql` — mount volumes there, not at `/var/lib/postgresql/data`.
- No ORM. All SQL lives in `.sql` files (migrations or sqlc queries).
- Dev tools pinned as Go tools in `go.mod` (`go get -tool`): `sqlc`, `goose`. `golangci-lint` installed as a binary.
- Amounts are `int64` cents. Never `float64` anywhere in money paths.
- Currency: only `"EUR"`.
- Fee: `round_half_even(amount_cents × 150 / 10000) + 25` cents by default; configurable via `IDEM_FEE_RATE_BPS` (default `150`) and `IDEM_FEE_FIXED_CENTS` (default `25`). Fee is fixed at creation and stored in `workflows.input`.
- Outbound step key: `hex(sha256("<workflow_uuid>:<step_name>:<generation>"))`, lowercase canonical UUID, decimal generation. Stored on the step row, never recomputed.
- `charge` step: `max_attempts = 8`, `generation = 0`, `status = 'PENDING'`.
- All IDs are UUIDv7.
- Nothing is acknowledged with 2xx before `COMMIT` succeeds.
- Status values are upper-case text guarded by `CHECK` constraints, exactly as listed in design §8.2/§8.3.
- Commit messages: Conventional Commits; **no `Co-Authored-By` or other attribution trailers.**

## Decisions this plan makes (not in the spec)

- Replays return the **original status code (201) and byte-identical body**, plus header `Idempotent-Replayed: true` (Stripe behaviour). Design §9.2 said "200"; Task 5 updates the doc.
- Only successful creations are stored. Requests rejected by validation (400/422) never touch the key table, so a client can fix the body and reuse the key.
- The fingerprint is computed from the *decoded request struct* re-marshalled by `encoding/json` → insensitive to whitespace and JSON key order.
- Concurrent same-key requests: the loser blocks on the unique index until the winner commits, then replays. `SET LOCAL lock_timeout` (default `5s`) bounds the wait → `409 idempotency_key_in_use`.
- Static API tokens: `IDEM_API_TOKENS="client_a=token1,client_b=token2"`; token → `client_id`; keys are scoped per `client_id`.

## Review Focus

1. **Retry with reformatted JSON** (different whitespace / key order, same values) must replay, not 422 → test in Task 2 (`TestFingerprint_IgnoresFormatting`) and Task 5 e2e.
2. **Fee config changes between original request and retry** must replay the original fee, not recompute → Task 3 `TestSubmit_ReplayIgnoresNewFeeConfig`.
3. **Same key from two different clients** must create two independent workflows → Task 3 `TestSubmit_KeyScopedPerClient`.
4. **Amount too small to cover the fee** (e.g. 25 cents) must be rejected with 422, not create a workflow with a non-positive payout → Task 2 validation table.
5. **Database unreachable** must make `/readyz` return 503 and requests return 500 with no internal error text leaked → Task 4 tests.

```sql
CREATE TABLE workflows (
  id          uuid        PRIMARY KEY,
  client_id   text        NOT NULL,
  type        text        NOT NULL CHECK (type IN ('payment_payout')),
  status      text        NOT NULL CHECK (status IN ('PENDING','RUNNING','SUCCEEDED','FAILED',
                                                     'COMPENSATING','COMPENSATED','NEEDS_ATTENTION')),
  input       jsonb       NOT NULL,
  version     bigint      NOT NULL DEFAULT 0,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE steps (
  id                 uuid        PRIMARY KEY,
  workflow_id        uuid        NOT NULL REFERENCES workflows(id),
  name               text        NOT NULL CHECK (name IN ('charge','payout','refund')),
  generation         int         NOT NULL DEFAULT 0 CHECK (generation >= 0),
  status             text        NOT NULL CHECK (status IN ('PENDING','RUNNING','IN_DOUBT','AWAITING_CALLBACK',
                                                            'SUCCEEDED','FAILED_PERMANENT','DEAD')),
  prior_status       text,
  idempotency_key    text        NOT NULL UNIQUE,
  attempt_count      int         NOT NULL DEFAULT 0,
  max_attempts       int         NOT NULL CHECK (max_attempts > 0),
  run_after          timestamptz NOT NULL DEFAULT now(),
  lease_owner        text,
  lease_epoch        bigint      NOT NULL DEFAULT 0,
  lease_expires_at   timestamptz,
  callback_deadline  timestamptz,
  provider_ref       text,
  last_error         text,
  first_attempted_at timestamptz,
  created_at         timestamptz NOT NULL DEFAULT now(),
  UNIQUE (workflow_id, name, generation)
);
CREATE INDEX steps_claimable ON steps (run_after) WHERE status IN ('PENDING','IN_DOUBT');

CREATE TABLE api_idempotency_keys (
  client_id           text        NOT NULL,
  key                 text        NOT NULL,
  request_fingerprint text        NOT NULL,
  workflow_id         uuid        REFERENCES workflows(id),
  response_body       jsonb,
  created_at          timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (client_id, key)
);
```

- Consumes: `store.IsLockTimeout`, `testutil.*` (Task 1); `PaymentInput`, `StepIdempotencyKey` (Task 2).
- Produces:
  - `workflow.NewSubmitter(pool *pgxpool.Pool, lockTimeout time.Duration) *Submitter`
  - `workflow.SubmitRequest struct { ClientID, IdempotencyKey, Fingerprint string; Input PaymentInput }`
  - `workflow.SubmitResult struct { Body json.RawMessage; Replayed bool }`
  - `(*Submitter).Submit(ctx context.Context, req SubmitRequest) (SubmitResult, error)`
  - `workflow.ErrKeyReuseMismatch`, `workflow.ErrKeyInUse` (sentinel errors)
  - `workflow.Created struct { WorkflowID uuid.UUID \`json:"workflow_id"\`; Status string \`json:"status"\`; AmountCents int64 \`json:"amount_cents"\`; FeeCents int64 \`json:"fee_cents"\`; Currency string \`json:"currency"\`; CreatedAt time.Time \`json:"created_at"\` }` — the stored/returned body.
  - Test hook (unexported field `beforeCommit func() error`, set via `export_test.go` `SetBeforeCommit(s *Submitter, f func() error)`).

`sqlc.yaml`: engine `postgresql`, schema `migrations`, queries `internal/store/queries`, gen go package `db`, out `internal/store/db`, `sql_package: pgx/v5`, `emit_pointers_for_null_types: true`, override `uuid` → `github.com/google/uuid.UUID`.

Queries in `submit.sql`: `InsertIdempotencyKey :execrows` (`ON CONFLICT (client_id, key) DO NOTHING`), `GetIdempotencyKey :one` (fingerprint, response_body), `InsertWorkflow :one` (returns `created_at`), `InsertStep :exec`, `SetIdempotencyKeyResponse :exec`.

`Submit` algorithm (one transaction):
1. `BEGIN`; `SET LOCAL lock_timeout = '<ms>ms'`.
2. `InsertIdempotencyKey`. Lock timeout → rollback, `ErrKeyInUse`.
3. 0 rows → `GetIdempotencyKey`; fingerprint differs → `ErrKeyReuseMismatch`; `response_body` NULL → error (invariant violated, never expected); else return `{Body, Replayed: true}`.
4. 1 row → new UUIDv7 workflow (`type='payment_payout'`, `status='PENDING'`, `input` = `PaymentInput` JSON), `charge` step (UUIDv7, gen 0, `PENDING`, `max_attempts` 8, key = `StepIdempotencyKey`), marshal `Created`, `SetIdempotencyKeyResponse`, run `beforeCommit` if set, `COMMIT`, return `{Body, Replayed: false}`.
Any error → rollback and return wrapped error.

- Create: `internal/api/server.go`, `internal/api/auth.go`, `internal/api/workflows.go`, `internal/api/errors.go`

**Interfaces:**
- Consumes: `workflow.*` from Tasks 2–3.
- Produces:
  - `api.Submitter interface { Submit(context.Context, workflow.SubmitRequest) (workflow.SubmitResult, error) }`
  - `api.Pinger interface { Ping(context.Context) error }` (satisfied by `*pgxpool.Pool`)
  - `api.Options struct { Tokens map[string]string /* token → clientID */; Fees workflow.FeeConfig; Logger *slog.Logger }`
  - `api.NewServer(opts Options, sub Submitter, db Pinger) http.Handler`

Routes: `POST /workflows`, `GET /healthz` (always 200 `{"status":"ok"}`), `GET /readyz` (200 if `Ping` succeeds within 2s, else 503 `{"status":"unavailable"}`). Health routes need no auth.

Error envelope: `{"error":{"code":"<code>","message":"<text>","field":"<optional>"}}`, `Content-Type: application/json`.

`POST /workflows` pipeline and responses:
| Condition | Status | `code` |
|---|---|---|
| Missing/invalid `Authorization: Bearer <token>` (compare every token with `subtle.ConstantTimeCompare`) | 401 | `unauthorized` |
| Missing `Idempotency-Key` | 400 | `idempotency_key_required` |
| Key not 1–255 chars of `0x21–0x7E` | 400 | `idempotency_key_invalid` |
| Body > 64 KiB (`http.MaxBytesReader`) | 413 | `body_too_large` |
| Malformed JSON, unknown field (`DisallowUnknownFields`), trailing data | 400 | `invalid_json` |
| `*workflow.ValidationError` | 422 | `validation_failed` (+ `field`) |
| `ErrKeyReuseMismatch` | 422 | `idempotency_key_reused` |
| `ErrKeyInUse` | 409 | `idempotency_key_in_use` |
| Any other error | 500 | `internal` — message `"internal error"`, real error only logged |
| Success / replay | 201 | body = `SubmitResult.Body` verbatim; replay adds `Idempotent-Replayed: true` |

Log one `slog` line per request with `client_id`, `idempotency_key`, `status`, `replayed`, `workflow_id` (when known).
