# Slice 1.6 — Operability — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make idem operable by a human on call. Every parked workflow (`NEEDS_ATTENTION`) gets a safe, audited way out through `idem admin`. Prometheus metrics answer "what is stuck, and why?" without reading the database by hand. Alert rules and a runbook tell the on-call engineer what each signal means and which action to take. This completes milestone 1.

**Architecture:**
- **Admin operations** are engine functions (`internal/engine/admin.go`). Each is one transaction that compare-and-swaps the expected step and workflow state, bumps the fencing token on any ownership change (D7), and writes an `admin_actions` audit row. They reuse the steps' own hooks, so ledger postings and saga transitions are identical to the automatic path. `idem admin` is a thin CLI over them.
- **Metrics** live in `internal/metrics`, a single registry with typed helpers:
  - workers count attempt outcomes, fenced commits and provider latency
  - the sweeper turns database state into gauges
  - the API counts submissions
- **Exposure:** the API serves `/metrics`; workers and sweepers serve it on `IDEM_METRICS_ADDR`.
- **Monitoring and docs:** compose gains Prometheus with alert rules; a runbook maps each `dead_reason` to an investigation and an admin action.

**Tech Stack:** As before, plus `github.com/prometheus/client_golang v1.24.0` (the newest version supporting Go 1.25) and the `prom/prometheus` image in compose.

**Spec:** `docs/design.md` — §5 (principles 4, 8), §8.2, §11.4 (admin actions), §13, §15 ("Observability (M1 minimum)"), §16 (D6, D7).

## Global Constraints

- Every earlier constraint holds (Go 1.25 pins, `GOTOOLCHAIN=local`, no attribution trailers in commits).
- **Admin actions:**
  - **Audit:** every mutating action requires `--reason` (non-empty) and writes exactly one `admin_actions` row in the same transaction as its change. The actor comes from `IDEM_ADMIN_ACTOR`, or `$USER` if unset.
  - **Parked work only:** a mutating action only touches a workflow in `NEEDS_ATTENTION` and a step in `DEAD` or `FAILED_PERMANENT`. Anything else is refused with `ErrNotActionable` and changes nothing.
  - **Fencing:** any action that hands a step back to workers bumps `lease_epoch`.
  - **Invariants:** after any action, and after workers drain, I1–I7 hold.
- **New idempotency keys are minted only by `new-generation`.** It requires `--reason` and `--confirm-no-effect` (D6, principle 4).
- **Metrics:**
  - names are prefixed `idem_`
  - **no workflow, step or key IDs in labels** (bounded cardinality)
  - histograms only for latencies
- Reconcile-from-DB gauges are computed by the sweeper. Several sweepers export identical values, which is harmless for gauges.

## Decisions this plan makes (not in the spec)

- **Six admin actions instead of the spec's three.** Each resolves one concrete parked situation without hand-written SQL. `resolve --as …` from §11.4 is replaced by `confirm-step`, `compensate` and `fail`, which also keep the ledger and the saga consistent.

  | Command | When | Effect |
  |---|---|---|
  | `list [--reason R]` | always (read-only) | parked workflows with step, `dead_reason`, attempts, last error, age |
  | `retry-step <step> --reason` | transient cause fixed; safe to retry the **same key** | step → `IN_DOUBT` if its dead reason means money may have moved, else `PENDING`; `attempt_count = 0`; `dead_reason = NULL`; `lease_epoch + 1`; workflow → `RUNNING` (charge/payout) or `COMPENSATING` (refund) |
  | `new-generation <step> --reason --confirm-no-effect` | human verified **no effect** happened and wants to send again | old step stays `DEAD` (history); new step `generation + 1` with key `StepIdempotencyKey(wf, name, gen+1)`; workflow back to active |
  | `confirm-step <step> --provider-ref REF --reason` | human verified the effect **did** happen | step → `SUCCEEDED` with `provider_ref`; the step's `OnSuccess` runs (ledger + saga advance) exactly as if the worker had seen it |
  | `compensate <workflow> --reason` | parked **payout**, human verified the merchant was **not** paid | refund step created from the charge reference; workflow → `COMPENSATING` |
  | `fail <workflow> --reason` | parked **charge**, human verified the customer was **not** charged | workflow → `FAILED` |

- **`ChargeProviderRef`** returns the highest-generation succeeded charge (`ORDER BY generation DESC LIMIT 1`), since `new-generation` can create more than one charge step.
- **`refund_charge_ref` is made immutable** by a trigger (deferred review minor). The test that corrupted it uses `session_replication_role = replica` instead.
- **The sweeper's per-workflow "stuck" log lines are replaced** by one summary line per tick plus gauges (deferred review minor: noise).
- **Two deferred review minors are folded in:**
  - a gauge for steps over their attempt limit
  - fenced-commit and in-doubt-resolution counts in the chaos report

## Review Focus

1. **An admin action racing a worker.** The workflow is no longer parked (or the step is running) → the action must be refused, and the database left unchanged → Task 2 `TestAdmin_RefusesNonParkedWork`.
2. **`new-generation` must be impossible** on a `SUCCEEDED`, `RUNNING`, `IN_DOUBT` or `PENDING` step, and must fail without `--confirm-no-effect` → Task 2 `TestAdmin_NewGenerationGuards`, Task 3 CLI test.
3. **`confirm-step` must post the ledger exactly once**, keep I3 true, and be refused a second time → Task 2 `TestAdmin_ConfirmStepPostsOnceAndAdvances`.
4. **Metric labels must stay bounded:** no IDs, keys or error text → Task 4 `TestMetrics_NoUnboundedLabels`.
5. **A retried in-doubt step must stay in doubt (sticky)**, so its next exhaustion still says money may have moved → Task 2 `TestAdmin_RetryStepKeepsDoubtSticky`.

**Schema:**
```sql
CREATE TABLE admin_actions (
  id          uuid        PRIMARY KEY,
  at          timestamptz NOT NULL DEFAULT now(),
  actor       text        NOT NULL CHECK (actor <> ''),
  action      text        NOT NULL CHECK (action IN ('retry_step','new_generation','confirm_step','compensate','fail')),
  workflow_id uuid        NOT NULL REFERENCES workflows(id),
  step_id     uuid        REFERENCES steps(id),
  reason      text        NOT NULL CHECK (length(trim(reason)) > 0),
  details     jsonb       NOT NULL DEFAULT '{}'
);
CREATE INDEX admin_actions_workflow ON admin_actions (workflow_id);
```

### Task 2: Admin operations

**Files:** Create `internal/store/queries/admin.sql`, `internal/engine/admin.go`; Test `internal/engine/admin_test.go`.

**Interfaces — Produces:**
- `engine.ErrNotActionable`
- `engine.Admin{ Pool *pgxpool.Pool; Steps map[string]Step; Actor string }`; `engine.NewAdmin(pool, steps []Step, actor string) *Admin`
- `(*Admin).ListParked(ctx, reason string) ([]ParkedWorkflow, error)`
  - `ParkedWorkflow{ WorkflowID, StepID uuid.UUID; Step, StepStatus, DeadReason, LastError, CustomerID, MerchantID string; Attempts int32; AmountCents int64; ParkedFor time.Duration }`
  - the parked step is the workflow's `DEAD` or `FAILED_PERMANENT` step with the highest generation
- `(*Admin).RetryStep(ctx, stepID uuid.UUID, reason string) error`
- `(*Admin).NewGeneration(ctx, stepID uuid.UUID, reason string, confirmNoEffect bool) (uuid.UUID, error)` — returns the new step ID; `!confirmNoEffect` → error before any write
- `(*Admin).ConfirmStep(ctx, stepID uuid.UUID, providerRef, reason string) error`
  - **Order:** in one transaction, workflow `NEEDS_ATTENTION → RUNNING|COMPENSATING` (by step: refund → `COMPENSATING`), then step → `SUCCEEDED` (with `provider_ref` set and `dead_reason` cleared), then `Steps[name].OnSuccess`.
  - **Why this order:** the hook's own CAS then sees the expected workflow state.
- `(*Admin).Compensate(ctx, workflowID uuid.UUID, reason string) error` — only when the parked step is a `payout`; refund created through `newStep` with `ChargeProviderRef`.
- `(*Admin).Fail(ctx, workflowID uuid.UUID, reason string) error` — only when the parked step is a `charge`; workflow → `FAILED`.
- **Common to every mutation:**
  - empty reason → error
  - every row it changes is matched against its expected state (CAS); 0 rows → `ErrNotActionable`
  - an audit row whose `details` records the before/after statuses and, where relevant, `provider_ref` or the new key's generation

### Task 3: `idem admin` CLI

**Files:** Create `cmd/idem/admin.go`, `cmd/idem/admin_test.go`; Modify `cmd/idem/main.go`.

**Interfaces — Produces:**
- `idem admin list [--reason R] [--json]` prints a table:

  ```
  WORKFLOW  STEP  STATUS  REASON  ATTEMPTS  PARKED FOR  LAST ERROR
  ```

  `LAST ERROR` is truncated to 60 chars. `--json` prints the `ParkedWorkflow` list.
- `idem admin retry-step <step-id> --reason R`
- `idem admin new-generation <step-id> --reason R --confirm-no-effect`
- `idem admin confirm-step <step-id> --provider-ref REF --reason R`
- `idem admin compensate <workflow-id> --reason R`
- `idem admin fail <workflow-id> --reason R`
- **Config:** each command needs only `IDEM_DATABASE_URL`. The actor is `IDEM_ADMIN_ACTOR` or `$USER`. The CLI registers the charge, payout and refund steps with a `nil` provider client, since admin only uses their hooks.
- **Output and exit codes:** success prints one line naming what changed. `ErrNotActionable` prints the current statuses and exits 1. A missing flag or bad UUID exits 2.
