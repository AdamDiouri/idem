# Slice 2.1: Async Payouts and Deadline Polling — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Payouts become asynchronous. The provider answers `202 pending`, the step waits in `AWAITING_CALLBACK`, and workers poll `GET /payouts/{id}` past the callback deadline until the payout is paid or failed. There are no webhooks yet, so polling alone must complete every payout (F18).

**Architecture:** Polling reuses the claim → call → complete machinery. An `AWAITING_CALLBACK` step past its deadline is claimable like `PENDING`/`IN_DOUBT`; the claim marks the attempt as kind `poll`, and the worker calls `Poll` instead of `Execute`. Polls have their own counter (`poll_count`) and never create doubt: a crashed poll goes back to `AWAITING_CALLBACK`, not `IN_DOUBT`. The pivot safety rule reads the step's history of *send* attempts.

**Tech Stack:** Go 1.25, Postgres 18, sqlc v1.30.0 (`sqlc.arg` syntax), goose, pgx/v5, testcontainers, testify.

**Spec:** `docs/superpowers/specs/2026-11-10-milestone-2-design.md` §4.1, §4.2, §4.5, §7, §8 (F18), §9 (I4), §10 (slice 2.1). M1 spec: `docs/design.md`.

## Global Constraints

- Go 1.25 with `GOTOOLCHAIN=local`; add no dependencies.
- Queries are written in sqlc with `sqlc.arg(...)`, never `@name`; regenerate with `make generate`.
- Every provider call keeps the step's stored idempotency key (D6). A poll sends nothing, so it can never create doubt (D17).
- The payout is posted to the ledger only when it is **paid**, in the same transaction as the step's `SUCCEEDED` (D2).
- The pivot safety rule: a payout that ends `failed` after any earlier ambiguous **send** attempt is `DEAD` with `permanent_after_in_doubt`, never refunded.
- `NEEDS_ATTENTION` exits only through an audited admin action (D18).
- Defaults: `IDEM_CALLBACK_DEADLINE=10m`, `IDEM_CALLBACK_MAX_POLLS=8`, fake provider `FAKEPROVIDER_PAYOUT_SETTLE=2s`.
- Commits never carry a `Co-Authored-By` line.
- **A known red window:** from Task 1, the fake provider answers payouts with `202`, which the engine can't complete until polling lands in Task 5. Between them, engine and chaos tests that drain a payout are expected to fail; each task runs only the packages its steps name. From Task 5 on, `make test`, `make lint` and `make build-release` pass.

## Review Focus

1. **A worker crashing mid-poll** must leave the step `AWAITING_CALLBACK` (not `IN_DOUBT`), and a later `failed` must refund, not park. Test: Task 5 `TestFlow_PollCrashIsNotDoubt`.
2. **A provider that never settles** must end in a bounded `DEAD callback_unresolved`, never an endless poll loop. Test: Task 5 `TestFlow_UnsettledPayoutGoesDeadAfterMaxPolls`.
3. **`confirm-step` with the payout's own `po_` reference** (the obvious action after `callback_unresolved`) must be accepted, not refused as "already recorded". Test: Task 5 `TestAdmin_ConfirmCallbackUnresolvedWithOwnRef`.
4. **A crash after the provider accepted the payout but before we recorded it** must, on re-send, get the same payout ID and wait, not create a second payout. Test: Task 5 `TestFlow_AcceptedThenTimeoutWaitsOnSamePayout`.
5. **Attempt numbering after an admin retry of `callback_unresolved`** (sends after polls) must not collide in `step_attempts`, and many polls must not trip `idem_steps_over_attempt_limit`. Test: Task 5 `TestAdmin_RetryCallbackUnresolvedResumesPolling`.

### Task 3: Schema and queries — waiting, polling, attempt kinds

**Files:**
- Create: `migrations/00008_async_payouts.sql`
- Modify: `internal/store/queries/engine.sql`, `internal/store/queries/admin.sql`, `internal/engine/claim.go`, `internal/engine/complete.go`, `internal/engine/step.go`
- Test: `internal/engine/store_test.go`

**Interfaces:**
- Produces (schema):
  - `step_attempts.kind text NOT NULL DEFAULT 'send' CHECK (kind IN ('send','poll'))`
  - `steps.poll_count int NOT NULL DEFAULT 0`
  - the attempt outcome check adds `'AWAITING_CALLBACK'`
  - the `dead_reason` check adds `'callback_unresolved'`
  - the `steps_claimable` index is recreated over `status IN ('PENDING','IN_DOUBT','AWAITING_CALLBACK')`
  - a `Down` section reverses all of it
- Produces (queries):
  - **`ClaimStep`:** also claims `AWAITING_CALLBACK` steps with `run_after <= now()`. For those it increments `poll_count` (not `attempt_count`). It returns `provider_ref`, `poll_count`, and `send_doubt` = `EXISTS` of a `send` attempt with outcome in `('IN_DOUBT','ABANDONED','DEAD')`. `DEAD` is included on purpose: conservative, because an exhausted ambiguous attempt is recorded as `DEAD`.
  - **Attempt numbers:** `attempt_no` = `attempt_count + poll_count` after the increment. Both counters only grow, so attempt numbers stay unique across sends and polls.
  - **`InsertStepAttempt`:** takes `kind`.
  - **`CompleteStep`:** status `AWAITING_CALLBACK` sets `run_after = now() + retry_ms` and `callback_deadline` to the same instant. Other statuses set `callback_deadline = NULL`.
  - **`ReclaimExpiredLeases`:** a `RUNNING` step whose `prior_status = 'AWAITING_CALLBACK'` (a poll) returns to `AWAITING_CALLBACK` with `run_after = callback_deadline = now()`; every other step goes `IN_DOUBT`, as now. The abandoned attempt is matched by `attempt_count + poll_count`.
  - **`StepHadInDoubtAttempt`** (admin): only `send` attempts count.
  - **`ProviderRefInUse`:** gains `sqlc.arg(step_id)` and excludes that step.
- Produces (Go):
  - `ResultAwaitingCallback ResultKind = "AWAITING_CALLBACK"`
  - `DeadCallbackUnresolved = "callback_unresolved"`
  - `ClaimedStep` gains `AttemptNo int32` (the `step_attempts` row), `PollCount int32`, `ProviderRef string` and `SendDoubt bool`. `Attempt` keeps meaning *send* attempts, compared with `MaxAttempts`.
  - `Claim` records kind `poll` when the claimed step was `AWAITING_CALLBACK`.
  - `Complete` uses `s.AttemptNo` for `FinishStepAttempt` and accepts `ResultAwaitingCallback` with no hook.

### Task 4: Decision rules — acceptance, polls, pivot from history

**Files:**
- Modify: `internal/engine/decide.go`
- Test: `internal/engine/decide_test.go` (internal package)

**Interfaces:**
- Consumes: Task 2 classes; Task 3 `ClaimedStep` fields and result/reason constants.
- Produces:
  - **`decide(s ClaimedStep, out provider.Outcome, b Backoff, inFlightDelay, callbackDeadline time.Duration, pivot bool) Result`.** The new parameter is `callbackDeadline`.
    - `Accepted` → `ResultAwaitingCallback` with `ProviderRef` and `RetryDelay = callbackDeadline`.
    - The pivot rule becomes `pivot && (s.PriorStatus == "IN_DOUBT" || s.SendDoubt)`.
  - **`decidePoll(s ClaimedStep, out provider.Outcome, b Backoff, maxPolls int32, pivot bool) Result`:**
    - `Success` → `ResultSucceeded` with `ProviderRef = s.ProviderRef`
    - `Permanent` → `ResultFailedPermanent`, or `ResultDead`/`DeadPermanentAfterInDoubt` when `pivot && s.SendDoubt`
    - `Pending` → `ResultAwaitingCallback` with `RetryDelay = min(b.Cap, b.Base + b.Delay(s.PollCount))`
    - anything else (a failed poll) → `ResultAwaitingCallback` with `RetryDelay = b.Base`, never `IN_DOUBT`
    - `Pending` or a failed poll with `s.PollCount >= maxPolls` → `ResultDead` with `DeadCallbackUnresolved`
    - `Error` is set from `out.Err` as in `decide`
