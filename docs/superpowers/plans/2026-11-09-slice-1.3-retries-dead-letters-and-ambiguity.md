# Slice 1.3 — Retries, Dead Letters and Ambiguity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every step either succeeds, fails permanently, or ends in a loud, named dead-letter state within bounded time. Retries use exponential backoff with full jitter. Definite "no effect" outcomes (429, refused connections) are told apart from ambiguous ones. A step whose idempotency key is near the provider's retention limit is resolved by lookup, never by a new key.

**Architecture:** The worker turns a provider outcome plus the step's history into one of five results: SUCCEEDED, FAILED_PERMANENT, IN_DOUBT, RETRY_NO_EFFECT and DEAD. "May have moved money" is **sticky**: once a step has been ambiguous, a later definite-no-effect answer does not clear it. When attempts run out, the step becomes `DEAD` and its workflow becomes `NEEDS_ATTENTION`, in the same fenced completion transaction. The sweeper also reports stuck workflows. Shutdown gets a bounded grace period.

**Tech Stack:** Same as slice 1.2; no new dependencies.

**Spec:** `docs/design.md` — §5 (principles 2, 3, 4, 8), §8.2–8.3, §9.1 Phase B, §9.3, §9.4, §11.1, §11.2, §12 (F7–F9, F11, F22, F23, F24, F25), §16 (D5, D6).

## Global Constraints

- Everything from slice 1.2's constraints still holds (Go 1.25 pins, DB clock only, every ownership change bumps `lease_epoch`, fenced completion predicate, stored keys never recomputed, no attribution trailers in commits).
- **Never mint a new idempotency key automatically** (D6). Key past retention + unknown at provider ⇒ `DEAD`, not a retry.
- **Sticky ambiguity:** a step that was ever `IN_DOUBT` returns to `IN_DOUBT` (never `PENDING`) on a definite-no-effect answer.
- Backoff: `delay = rand(0, min(cap, base · 2^(attempt−1)))`, defaults `base = 2s`, `cap = 5m`; a provider `Retry-After` raises the delay to at least that value.
- Attempt limits come from `steps.max_attempts` (charge: 8, already stored).
- `DEAD` always sets the workflow to `NEEDS_ATTENTION` in the same transaction and records a `dead_reason`.

## Decisions this plan makes (not in the spec)

- **New provider class `NoEffect`** for outcomes where the request provably never reached the provider (`429`, dial/DNS errors). `409` stays `Ambiguous` but marks `InFlight` for a short retry (the base delay, no growth).
- **`dead_reason` column** with values `attempts_exhausted_no_effect`, `attempts_exhausted_in_doubt`, `key_expired_unknown`. The alert text in logs comes from it. "In doubt" reasons say that money may have moved.
- **Key-age check uses `first_attempted_at`** (DB clock). Lookup happens when `PriorStatus = IN_DOUBT` and `key_age ≥ retention − margin`. Retention and margin are config (`24h` / `1h`).
- **Stuck-workflow reporting** (§11.1 row 3) is a WARN log per workflow in this slice. Metrics arrive in slice 1.6.
- **Two deferred review minors are folded in** because they touch the same code: a partial index for the sweeper, and a currency check on successful charges.
- **Shutdown grace:** in-flight step work is cancelled `IDEM_SHUTDOWN_GRACE` (default `15s`) after SIGTERM; compose `stop_grace_period: 20s`.

## Review Focus

1. **A step that was ambiguous, then gets a 429, must stay `IN_DOUBT`**: if it went back to `PENDING`, its eventual `DEAD` reason would wrongly say "no money moved" → Task 4 `TestWorker_NoEffectAfterInDoubtStaysInDoubt`.
2. **Attempts exhausted on an ambiguous step must say money may have moved**, and on a pure no-effect step must say it did not → Task 4 `TestWorker_DeadReasons`.
3. **Key expired at the provider and lookup returns 404** must go `DEAD` without any new charge attempt → Task 5 `TestWorker_KeyPastRetentionUnknownIsDead_F23`.
4. **A huge or garbage `Retry-After`** must not stall a step for days or crash parsing; it is capped at backoff `cap` → Task 2 `TestRetryAfter` table.
5. **`DEAD` must happen exactly once even with a stale worker racing a reclaim** — it goes through the same fenced completion → Task 4 `TestWorker_DeadIsFenced`.

Classification changes (rest unchanged):
